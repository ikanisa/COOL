# Roster import provenance — contract 1

Migration: `20260930100000_roster_import_provenance.sql` (142). This is a coordinated database/Edge/Admin change; deploy the compatible callers with the migration. The two legacy public raw-row roster writers fail closed after migration 142.

## Authority and retained evidence

The trusted upload Edge service verifies the authenticated user through Auth, derives the JWT session identifier, validates the uploaded format and hashes the **actual received bytes**. Caller-supplied actor IDs, hashes, sizes, model names and validation claims are rejected. SQL independently checks the current actual user/session, verified approved Admin identity, `collections.moderate` and `users.read`, and the `hybrid_member_onboarding` feature flag. The migration 141 gate is acquired before the Admin roster and Auth locks.

Source receipts, extraction attempts/results, human review revisions and commit acknowledgements are private and immutable. They store bounded metadata and reviewed roster rows. Original uploaded files, raw provider bodies and secrets are not retained. The internal consent receipt version records the product interaction; it is not legal approval or a determination of lawful retention. P05 retention/access/deletion policy remains separate.

Every import is owned by its actual actor **and original Auth session**. Another account or a new session must start a new import. Only the actor can read its private receipt through the authorized RPC. The service role can register bounded upload/extraction facts; it cannot finalize membership or financial records through these functions.

## Browser upload request

`prepare-roster-import` accepts `contract_version: 1`, a stable UUID `request_id`, and `source_type: text | csv | txt | xlsx | pdf | image`. Pasted `text` carries `content`. Every uploaded format carries `filename`, `mime_type`, and `content_base64`. XLSX also carries `derived_content`, a TSV generated by the client. PDF/image requests require `ai_consent: true` and `consent_version: "roster-ai-extraction-v1"`.

An XLSX receipt binds the actual original uploaded bytes and separately hashes the received TSV. Its `detected_type: "zip_container"` proves the server's framing check only. `derived_assurance: "client_derived_tsv"` explicitly states that the server did not verify the TSV against workbook cells. A client-provided digest is never treated as verified original-byte evidence.

## Trusted service RPCs

All arguments below are required; nullable arguments must be explicit JSON null. Only `service_role` has EXECUTE.

### `create_roster_import_source`

| Argument | Type | Meaning |
| --- | --- | --- |
| `p_actor_id`, `p_session_id`, `p_request_id` | UUID | Auth-derived user/session and stable upload request |
| `p_source_kind` | text | `text`, `csv`, `txt`, `xlsx`, `pdf`, `image` |
| `p_original_sha256` | text | Lowercase SHA-256 of the actual received original bytes |
| `p_original_size` | bigint | 1–512,000 for text/CSV/TXT; 1–5,242,880 for binary formats |
| `p_client_filename` | text | Bounded display filename; pasted text uses `pasted-roster.txt` |
| `p_declared_mime` | text | Bounded declared MIME; never described as content verification |
| `p_detected_type` | text | `utf8_text` for text/TXT, `utf8_csv` for CSV, `zip_container` for XLSX, validated MIME for PDF/image |
| `p_derived_sha256`, `p_derived_size` | text, bigint | XLSX received TSV hash and 1–512,000-byte size; otherwise null |
| `p_ai_consent` | boolean | True for PDF/image; false otherwise |
| `p_consent_version` | text | Exactly `roster-ai-extraction-v1` for AI; otherwise null |
| `p_ai_metadata` | JSON object | AI only: exact `{provider:"openai",model:<1–128 chars>,prompt_version:"roster-extraction-v1"}`; otherwise null |

The source and AI attempt receipt are committed **before** contacting the provider. No provider call is permitted if this RPC fails. Response fields:

```text
{contract_version:1, ok:true, request_id:UUID, import_id:UUID,
 source_sha256:lower64, source_size:integer, source_kind:SourceKind,
 extraction_id:UUID|null, expires_at:timestamp,
 derived_sha256:lower64|null, derived_assurance:"client_derived_tsv"|null,
 state:"awaiting_preview"|"preview_ready"|"failed", replayed:boolean,
 completed_preview:PreviewReceipt|null, error_code:SafeError|null}
```

An exact upload-request replay returns the cached **initial** completed preview or immutable failure, so Edge does not call the provider again. A duplicate while its first attempt awaits completion fails `roster_import_in_progress`. If an attempt was interrupted, a deliberate new request/upload starts a new receipt. This does not silently retry a provider call. Changed content or metadata under the same request ID fails `roster_request_conflict`.

### `complete_roster_import_preview`

Arguments: `p_import_id uuid`, `p_actor_id uuid`, `p_session_id uuid`, `p_candidates jsonb`, `p_processing_metadata jsonb`.

Candidates are an array of 1–500 exact objects `{source_row: integer 1..2147483647, member_name: string, momo_name: string, momo_number: string, confidence: number 0..1}`. Raw names are bounded to 480 Unicode code points and phones to 32; normalized valid names remain 2–120. The existing provider schema remains stricter at 120 raw name code points. Total candidate JSON is bounded to 512,000 bytes. Provider candidates and deterministic parsing may contain correctable names/phones; malformed fields or oversized inputs are rejected. SQL computes issues, canonical rows and hashes itself.

Processing metadata is exactly `{processing_method:"deterministic"|"openai_structured_extraction",provider_response_sha256:lower64|null,provider_response_id:string|null}`. Both provider fields are non-null only for AI; response ID is at most 256 characters. No provider body is accepted or retained. The completed immutable revision is a preview, not a reviewed commit authorization.

### `fail_roster_import_preview`

Arguments: `p_import_id uuid`, `p_actor_id uuid`, `p_session_id uuid`, `p_error_code text`.

Allowed error codes: `roster_extraction_failed`, `roster_extraction_timeout`, `roster_extraction_refused`, `roster_extraction_incomplete`, `roster_provider_response_invalid`, `roster_provider_response_too_large`, `roster_preview_invalid`, `roster_extraction_unavailable`.

Response: `{contract_version:1,ok:true,import_id:UUID,state:"failed",error_code:SafeError,replayed:boolean}`. An exact repeat returns the same failure; conflicting completion/failure is denied. Failure receipts contain no upstream text.

## Authenticated operator RPCs

Only `authenticated` has EXECUTE. The actor/session are derived from Auth claims and checked against live Auth data; neither is a caller parameter.

### `admin_review_roster_import`

Arguments: `p_import_id uuid`, `p_parent_revision_id uuid`, `p_rows jsonb`, `p_reason text`, `p_request_id uuid`.

Rows contain exactly `{member_name:string,momo_name:string,momo_number:string}`. All 1–500 rows must be valid together. Names normalize whitespace, contain 2–120 Unicode code points, contain no remaining controls and cannot start with `=`, `+`, `-` or `@`. Phone formatting removes whitespace, parentheses, periods and hyphens, then admits only full Rwanda numbers supported by the existing SQL canonicalizer: `07[2389]…`, `2507[2389]…`, or `+2507[2389]…`, canonicalized to `+250…`. Duplicate canonical phones are rejected. Reason is 8–500 trimmed characters.

The parent must be the latest revision of this import. Each correction creates a new immutable revision linked to that parent, original source, and extraction attempt. At most 20 revisions including the first preview are accepted per import. No “copy to editor” action discards AI lineage. An exact review-request retry returns its original revision; changed content under its request ID fails.

### PreviewReceipt

```text
{contract_version:1,ok:true,import_id:UUID,source_sha256:lower64,
 source_kind:SourceKind,revision_id:UUID,parent_revision_id:UUID|null,
 revision_number:integer,reviewed_rows_sha256:lower64,
 can_submit:boolean,requires_human_review:boolean,
 processing_method:"deterministic"|"openai_structured_extraction"|"human_review",
 model:string|null,rows:PreviewRow[],row_count:integer,ready_count:integer,
 error_count:integer,normalized_rows:CanonicalRow[],expires_at:timestamp,
 source_receipt:SourceReceiptMetadata}
```

PreviewRow is Candidate plus `issues:string[]` and `ready:boolean`. Only a human-review revision has `can_submit:true` and `requires_human_review:false`. SQL SHA-256 is over its normalized ordered JSONB array rendered as PostgreSQL `jsonb::text`. This is a server-issued opaque binding token; clients do not recreate JSON serialization or compute a competing hash. Every commit recomputes it from stored normalized rows.

`SourceReceiptMetadata` is the exact immutable object `{request_id:UUID,source_size:integer,client_filename:string,declared_mime:string,detected_type:string,derived_sha256:lower64|null,derived_assurance:"client_derived_tsv"|null,extraction_id:UUID|null,ai_consent:boolean,consent_version:"roster-ai-extraction-v1"|null,parser_version:"collect-roster-parser-v1",schema_version:"collect-roster-rows-v1"}`. It is returned on every revision; the UI displays source/consent/derivation facts from it rather than inferring them from a checkbox. Parser and schema versions are server constants. Human review sets reviewed-row confidence to 1 and preserves the original model/extraction link; the initial immutable preview retains original AI confidence and issues. `can_submit` is also false for expired, superseded or consumed human revisions.

### `admin_get_roster_import`

Argument: `p_import_id uuid`. Response: `{contract_version:1,ok:true,import_id:UUID,state:"awaiting_preview"|"preview_ready"|"failed"|"committed",expires_at:timestamp,preview:PreviewReceipt|null,commit:CommitReceipt|null,error_code:SafeError|null}`. Read returns the latest revision. Session/permission/feature checks still apply to expired or committed receipts.

### `admin_commit_roster_import`

Arguments: `p_request_id uuid`, `p_import_id uuid`, `p_revision_id uuid`, `p_reviewed_rows_sha256 text`, `p_human_affirmed boolean`, `p_mode text`, `p_collection_id uuid`, `p_title text`, `p_reason text`.

- `p_human_affirmed` must be true; it explicitly attests that the operator reviewed every row.
- `p_mode="create"`: collection is null and title is 3–120 trimmed characters. The group, private share secret and entire roster are created atomically.
- `p_mode="existing"`: collection has `creation_origin="admin_assisted"`, `archived_at=null`, `visibility="private"`, `public_status="private"`, `currency="RWF"`, `diaspora_enabled=false`, and title is null. The entire roster is added atomically. `admin_get_collection` exposes these actual eligibility fields; the schema has no collection `country_code` or `is_active` field.
- The revision must be the latest human-reviewed revision; import/revision/hash must all agree. Reason is 8–500 trimmed characters. All calls recheck current authorization.
- One import can be committed once. No raw caller rows enter this writer. The service role cannot call it. It does not write payments, credits, ledger journals, balances or receipts.

CommitReceipt is exactly:

```text
{contract_version:1,ok:true,request_id:UUID,import_id:UUID,revision_id:UUID,
 reviewed_rows_sha256:lower64,collection_id:UUID,mode:"create"|"existing",
 roster_count:integer,share_code_ready:boolean,replayed:boolean}
```

The caller validates every UUID/hash binding, enum, integer and real boolean before displaying success. Missing or malformed fields are failures, with no fallback success counts. `share_code_ready` must be true in both modes: a missing share secret is created atomically, and an existing secret is preserved. The stable request ID binds **all** normalized commit arguments and the actor/session. A different request or payload cannot reuse a consumed import.

## Expiry, retries and errors

Preview authority expires 24 hours after source receipt creation. Revisions do not extend it. No new preview/review/commit is allowed after expiry. An exact **already successful** commit retry can return its historical acknowledgement after preview expiry, provided the original actor/session remains live and permissions and feature flag remain enabled; it performs no new membership writes. Account/session revocation prevents even that replay.

Stable errors use SQLSTATE 42501 for unavailable/unauthorized actors, 22023 for invalid input, and 55000 for expiry, immutable conflicts, superseded revisions or consumed imports. Principal messages include `roster_actor_unavailable`, `roster_session_required`, `roster_feature_disabled`, `roster_input_invalid`, `roster_rows_invalid`, `roster_request_conflict`, `roster_import_in_progress`, `roster_import_expired`, `roster_import_unavailable`, `roster_revision_superseded`, `roster_import_committed`, `roster_commit_conflict`, and `roster_provenance_required`. Existing identity/name/lifecycle conflicts from the private legacy writer become `roster_commit_conflict`; the entire group/membership operation rolls back. SQL revocation contention may also return migration141's 40001; retry the complete transaction, never a fragment or provider operation automatically.

Creation is bounded to 100 source receipts per actor per rolling 24 hours, serialized under the Admin roster lock. This is an implementation limit, not provider-budget approval. Hosted provider spend/rate controls and lawful retention remain separate readiness requirements.
