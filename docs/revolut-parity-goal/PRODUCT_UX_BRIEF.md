# Product and UX Brief

## User outcome

Collect users should be able to understand their group contribution position,
find or create a group, contribute through MoMo, review confirmed activity, and
manage their profile with the calm density and interaction confidence of the
verified Revolut references.

## Primary audiences

- Group contributors using compact Android and iOS phones.
- Group owners administering members, receiver details, invitations, and
  ledgers.
- Operators using the Admin PWA.
- Public visitors using Collect's web information surfaces.

## Core mobile journeys

1. Sign in with phone/WhatsApp OTP.
2. Review Home value and recent activity.
3. Discover or open a group.
4. Select a group and enter a contribution amount.
5. Review receiver and amount before MoMo handoff.
6. Return to the group and see only verified ledger activity.
7. Search and filter cross-group activity.
8. Create and manage a group.
9. Manage profile, privacy, notifications, appearance, account, and support.
10. Recover from offline, permission, validation, payment, and sync failures.

## Visual principles

- Compact command chrome.
- One dominant value or task per first viewport.
- Four or fewer circular quick actions.
- Dense divided panels rather than isolated cards for repeated rows.
- Near-black or route-specific immersive gradients.
- Inter with restrained 400–700 hierarchy.
- Sixteen-pixel routine cards, 20-pixel featured cards, 24-pixel sheets.
- Stable floating navigation.
- No decorative financial concepts unsupported by Collect.

## Success measures

- Every primary task is reachable and operable without hidden or duplicated
  controls.
- Critical screens remain usable at 200% text and compact width.
- Payment and ledger privacy invariants remain covered by tests.
- Visual QA contains no P0/P1/P2 mismatches.
- Full automated and available release-build gates pass.
