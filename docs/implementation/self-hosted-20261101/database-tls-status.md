# Native PostgreSQL TLS and restricted-login qualification — 2026-11-01

**All eight scenarios passed** using the actual `postgres.js 3.4.7` driver under
Deno 2.9.6 against a newly created PostgreSQL 17.11 cluster. The safe,
source-bound final result is `database-tls-final-native-result.json`. The final
run used only loopback port 55448 and stopped only that newly created cluster
afterward. Existing clusters on ports 55443 through 55447 were not modified or
stopped. The earlier eight-scenario result, `database-tls-native-result.json`,
remains unchanged and records its earlier source versions and port 55446.
Credentials, CA signing keys, leaf keys, URLs and raw process/server logs remain
outside the repository in the private qualification directory.

The certificates were generated by the unchanged production preparation helper
`scripts.self_hosted.prepare.tls_keys`. The CA signing key was moved out of the
database leaf directory by that helper. The fixture requires SCRAM authentication
and SSL on all TCP connections; it contains no trust-authentication rule.

The test connects to the isolated IP transport while explicitly asking TLS to
verify hostname `db`. The production adapter connects to the internal DNS name
`db` and supplies that same hostname/CA/verification policy. The qualification
does not override hostname verification or install the test CA into global
trust. It uses the same npm driver directly; the application's legacy loopback
fixture shortcut is not treated as an encrypted connection.

## Reproduction

The maintained orchestration harness is
`scripts/self_hosted/qualify_database_tls.py`, invoked as a module so that no
local file named `operator.py` can shadow Python's standard library. Its Deno
test is `scripts/supabase/testing/self-hosted-database-tls.ts`.

From the repository root, use explicit native PostgreSQL 17 binaries, the pinned
Deno executable and an existing locked npm cache. Both the private directory
and receipt file must be new; the fixed port must be unused:

```sh
python -m scripts.self_hosted.qualify_database_tls \
  --pg-bin /absolute/path/to/pg17/bin \
  --deno /absolute/path/to/deno-2.9.6 \
  --deno-cache /absolute/path/to/deno-cache \
  --private-directory /absolute/path/to/new-private-tls-fixture \
  --receipt /absolute/path/to/new-safe-tls-receipt.json
```

The command creates a fresh synthetic cluster, runs the negative and positive
checks, verifies source bytes did not change during execution, retains private
diagnostics and stops only its own exact data directory. It refuses an occupied
port or existing target directory. It does not discover a server by port and
signal it. No URL, password, HMAC/JWT/provider key or private certificate enters
command arguments or the public receipt. On failure, preserve that attempt and
use another fresh directory/receipt for a retry.

The receipt pins the Python/Deno harnesses, certificate helper, current
application connection adapter, deployment database validation, Deno lock,
driver package and driver source files. Only certificate hashes are included;
private key bytes are excluded. Deno's network permission was limited to
`127.0.0.1:55448`, and dependencies were loaded with `--frozen --cached-only`.

The final run was performed after the explicit port change, the provider
configuration/source-inventory changes in `prepare.py`, and the additive Hono
lock entry. Its before/after checks pin those actual current bytes. The earlier
receipt has not been relabeled or presented as evidence for the later file
hashes.

## Qualification boundary

This is actual native TLS, password authentication and restricted-role driver
behavior. The role/RLS tables are a small synthetic fixture. The original
application migrations were not applied in this TLS fixture, and the receipt
explicitly sets `original_application_rls_acceptance: false`. Application
authority and financial behavior are covered by their separate native SQL
receipts and the combined migration-chain qualification.

This result does not certify Docker networking, the deployed CA/leaf, production
key custody, certificate renewal, the pinned Supabase images, live provider
behavior, device traffic or whole-host restore. `docker_acceptance` and
`production_acceptance` remain false. No shared application runtime was changed
to obtain the passing result.
