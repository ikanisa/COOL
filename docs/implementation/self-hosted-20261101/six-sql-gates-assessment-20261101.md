## Current and historical authority boundaries

The SQL142/144/149 producer guards explicitly require historical migration counts and old `collect_hybrid`/public routines. Their source and receipts remain historical. The curated current baseline `20261020134444_collect_curated_platform_baseline.sql` provides the `app.roster_*` tables, immutable revision and intent triggers; `20261023002500_collect_admin_recent_email_source_upgrade.sql` updates current roster authority checks. This is a structural and authority change, not a license to apply old SQL to the current cluster or to recreate old response JSON by hand.

The retained bearer Admin path uses `CollectAdminRosterGateway` and its assisted-group flow. That gateway declares recovery support and calls draft, reload and fresh-session RPC names which the current roster dispatcher does not register; unknown operations return 501. The shipping cookie entrypoint `lib/main_admin_cloudflare.dart` disables the bearer client and installs `CloudflareAdminRepository`, whose inherited `openRosterImport` is unsupported. Its router exposes manual group/member operations but no roster-import or roster-recovery route. The cookie BFF is therefore a narrower, distinct surface; neither the retained bearer adapter nor its historical receipt is evidence that the cookie surface supports those journeys.
