A safe import cannot assume empty private state, silently downgrade trigger modes, or fabricate storage records and live sessions.

The next implementation must use a separate profile-bound adapter and an isolated current-schema fixture. It needs reviewed source/target identities and table/column dispositions; a controlled bootstrap and trigger strategy preserving exact modes and history; independent storage, principal, device and pending-obligation decisions; and positive populated readback plus rollback, tamper, concurrent-writer and uncertain-commit tests. The old promoter and its refusal must remain intact. The old `scripts/supabase/data_promote.test.mjs` fixture drops schemas and is suitable only for a separately allocated, guarded database. No such adapter, positive promotion, live-data access, provider effect or cutover was performed in this assessment.
