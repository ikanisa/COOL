# Collect MVP source audit — working checkpoint

This is an incomplete source audit and task map, not a production approval or a replacement for the original 36-task status. It records the owner's current scope: a fresh self-hosted Supabase deployment; existing Android and iOS app updates; SMS OTP and optional Collect-managed OpenFace enrollment and remote matching; automatically eligible private-group creation, public-group joining and contribution posting; Admin management of public groups and exceptions; local SMS services; and automatic wallet and group reconciliation. Existing historical data is not needed for the first launch.

## Audit coverage

The integration worktree inventory counted 114,377 Git-visible paths, of which 110,291 were under `docs/release/` and largely consist of preserved qualification and recovery material. The active-source inventories mechanically read 723 `lib`/Android/iOS files, 245 Supabase function and migration files, 814 deploy/script files, and 1,061 test/tool/vendor/web/release files. A mechanical byte read or hash is **not** a semantic review. The `lib/core/security` and Android `receiver_sms` directories were read in full, but a substantive file-by-file review of the repository remains incomplete. Scopes overlap, so these counts are not additive. Some exact duplicate bytes belong to platform variants, test baselines, vendored sources or historical evidence; do not delete them on hash equality alone.

Earlier synthetic test results are valid only for their recorded inputs and do not prove a production deployment, real payment, device or provider delivery. ## Launch tasks established so far

1. **Freeze and qualify a production candidate.** Reconcile the Admin transport source with a truthful new provenance record after actual qualification; include backend-selection, cross-realm byte chunks, pre-aborted input, cancellation, deadline and post-dispatch unknown-outcome coverage. The source also indicates immediately ready chunks could delay a timer; this is not yet reproduced. Do not rewrite historical provenance. Check the self-hosted web-server's earlier request buffering as a separate affected boundary. Resolve active dependency alerts and their source-bound toolchain guards without altering preserved historical evidence.
2. **Deploy local Supabase and SMS.** Bind an exact release and deployment profile, validate secrets/TLS and scoped Admin roles, and qualify both new-member registration and existing-member SMS OTP on real phones. Registration is disabled by default in the inspected application and local CLI configurations; the actual deployment's settings have not been verified. Private configuration may be incomplete, while production publication requires SMTP and CAPTCHA; the publication guard has a focused local regression. A local deterministic MoMo extraction option is not currently admitted by self-host configuration: the unpaused path requires the configured AI adapter and approval. Qualify a suitable local parser or an explicitly selected alternative.
3. **Integrate OpenFace.** Select and qualify the intended account-authentication capability from the owner's OpenFace platform; bind it to Collect's own account/session and consent, protect facial data and provide OTP fallback. Validate Android and iOS enrollment, matching, attack controls, recovery and supported device behavior. Existing local OpenFace source is not evidence that Collect has a production integration.
4. **Complete profiles and private groups.** Align the member and Admin MoMo number, optional code and update-response contracts, including verified-phone and same-session retry/readback checks. Add the requested distinct MoMo account name; the current member profile RPC omits it. Ordinary private-group creation currently stores a NULL payment destination. Implement and qualify the authorized beneficiary/payment-route flow and retain automatic eligible creation and invitation membership, without introducing routine Admin approval.
5. **Qualify public-group joining.** A client and backend candidate now joins an eligible public nonmember before preparing a contribution, with a separate public-group operation and protected private invitations. Its synthetic backend tests passed; Flutter, PostgreSQL concurrency and actual client/server tests are still outstanding. Verify the intended join timing, eligibility, retry and removed-membership policy, and complete public discovery beyond its current 100-group limit.
6. **Make qualifying MoMo contributions automatic.** Existing raw receipt ingestion is evidence with zero immediate financial effect; the traced current reconciliation path requires a distinct reviewer. Implement the owner's automatic eligibility, matching and exactly-once ledger transitions, reserving human intervention for exceptions. Do not claim provider-side settlement or refunds from ledger changes alone. Test ambiguous matches, duplicate and conflicting envelopes, retries, account/session changes and reversals.
7. **Reconcile provider wallet and group balances.** The parser can extract `wallet_balance_after_minor`, but canonical incoming-fact handling excludes failed/outgoing/reversal cases and its duplicate core-fact comparison omits wallet balance. Define conflict and ordering rules and test missing, stale, delayed or contradictory observations, fees, opening balances and unrelated wallet activity before asserting synchronization. Provide and verify the required per-group and member balances in Admin and mobile views against the same authorized ledger and reconciled wallet observations.
8. **Qualify SMS capture and confirmation.** The owner-directed Android gateway upload hold remains active; the inspected server gateway ingest route has no equivalent application-level hold, so older clients with valid credentials need separate containment and qualification. A server refusal cannot retract an HTTP body already transmitted. Member capture remains enabled by owner choice. Preserve queued evidence and uncertain acknowledgements. Implement and test the owner's automatic post-commit SMS confirmation path; the existing assisted operator flow and held dispatch do not prove it.
9. **Close member SMS session and retry risks.** Scope consent, capture and upload to the initiating session/operation and reconcile native queue acknowledgement against session transitions; native auth and queue currently use separate locks. The direct receipt wrapper generates an envelope ID if none is supplied, so a lost response followed by a fresh-ID retry can produce a second raw capture; no current in-repository caller or actual duplicate is established. Keep stable identities and a durable unknown-outcome path.
10. **Qualify Android and iOS updates.** The owner reports both apps were previously submitted and approved; treat releases as updates and verify current store identities and signing. Existing iOS release workflow references legacy endpoint values, and existing route/material-state integration fixtures contain expectations inconsistent with current group creation. Select the correct local-backend deployment profile and verify both platforms on real devices. Current integration tests frequently use fixture repositories and do not alone prove live OTP, OpenFace, MoMo or SMS.
11. **Operate and recover.** Use a fresh production database, monitor local services and gateway queues, and qualify encrypted backups and a safe restore for the actual deployment before accepting real contributions. The previously flagged recovery and roster actions remain out of scope for retry. Existing gateway retention/personal-data erasure and external-copy boundaries need qualification.

## Subsequent review and implementation checkpoint

- The self-hosted scheduler's temporary credential file is now created exclusively with mode 0600 and removed on readiness, serialization and operator exceptions. Six synthetic custody tests and nine existing operator tests passed. This does not prove cleanup after process death, failed unlink or a container retaining a mount.
- A public-join and signed-in discovery candidate has been authored. It adds a separate public-group RPC, preserves private invitation handling, refuses to reactivate removed memberships and joins before contribution preparation. Its fake-database Node tests passed 5 cases and the existing synthetic contribution-command Node suite passed 66. Ten changed Dart files passed a non-writing formatter/parse check; that is not type analysis or behavioral testing. The newly authored Flutter and PostgreSQL tests remain unrun: their existing space preflights are not met. Those fake tests do not establish Postgres locking, actual client behavior or device acceptance. Public discovery is currently limited to the latest 100 groups; the new RPC is not implemented in the retained legacy Cloudflare profile. Current user-facing source and test changes remain to be independently qualified before production.
- The member SMS session/acknowledgement race has a prepared synthetic characterization fixture but no executed reproduction; its launcher and resource profile are incomplete and prior space guards remain unmet. A proper fix must also account for existing synchronous auth-adoption contracts and distinguish the separately held gateway queue.
- Both Android and iOS release workflow sources omit the SMS-auth compile flag while the application defaults that flag to false. Bind and verify the correct local-backend profile and flags before producing either store update; source inspection does not establish the settings of a previously approved app.
- Self-host configuration now checks enabled OpenSMS application IDs, tokens, sender labels and dispatch TTLs against the signed OTP hook's runtime limits. Synthetic boundary coverage passed in 29 hook tests and 37 configuration and operator tests; this does not prove deployment configuration or real SMS delivery. Disabled staging drafts remain supported, and existing gateway and publication gates remain in force.
- The phone OTP gateway's `Future<void>` verification interface discards the verified-session response, and the screen later calls the profile repository using whatever session is then current. The repository checks the session it captures, but the verified response-to-screen-to-repository identity link is not proved. Bind that flow to a response-bound session witness and cover replacement, sign-out and A→B→A races without persisting or exposing the OTP or bearer. Existing repository fake-HTTP tests do not establish the full screen/gateway boundary.
- The mobile OTP entry and client require six digits, while the inspected backend and signed hook accept 6–10. Pin and verify the SMS code length for the target deployment or align both contracts. The application describes a 300-second challenge, the retained upstream describes a 60-second default for GoTrue SMS expiry, and the hook defaults its dispatch window to 120 seconds. Qualify the exact deployed settings together, including delayed delivery and resend, so an accepted message cannot be assumed to contain a still-valid code. No active mismatch or live expiry was observed.
- A fresh database still requires the exact migration inventory and a reviewed, source/profile/image-bound SQL10 realtime binding. Excluding historical import does not remove this installation qualification.
- Source inspection indicates the signed GoTrue SMS hook can accept an OTP into the generic gateway queue while gateway dispatch is paused or no device is ready. An accepted queue item is not a delivered OTP. This potential availability mismatch needs a synthetic hook-and-gateway test and an explicit admission/delivery contract; no actual missed delivery has been demonstrated.
- The local SMS gateway's maintenance handler covers expiry, OTP scrubbing, callbacks and alerts; a bounded active-source search found no non-test caller for its protected maintenance endpoint. An external operator may exist. Identify and qualify the actual scheduler and monitor its execution before launch. Current self-hosted health checks do not establish SMS maintenance, device readiness, queue age or actual delivery; qualify separate non-secret indicators for those conditions.
- The local OpenSMS service exposes its own device jobs, acceptances and events API. The checked-in `internal_gateway` Android sender uses a different signed Collect receipt-gateway protocol, and the bounded active-source search did not find an Android/iOS client for the OpenSMS device API. Locate and source-bind an existing compatible sender or implement and qualify an adapter before claiming real OTP or confirmation SMS delivery. An external sender may exist; no device was inspected.
- The native and Dart changes that add public discovery include tests of session replacement, cache downgrade and failure handling, but these tests have not been executed. The PostgreSQL integration file includes a member-roster step: do not execute a broad parent test without isolating the user's flagged roster/recovery work.
- The current mobile profile update sends a local `07...` MoMo number and expects an object response, while the canonical Supabase update accepts international `250...` form and returns `null`; the UI also permits an empty optional MoMo code while that server handler rejects it. Source tracing therefore indicates the normal profile-save path cannot complete against that handler; this has not been runtime-reproduced. Align canonical number, optional code, verified-phone/provider checks, response and same-session durable retry/readback contracts. Add the requested distinct account-name field with the corresponding schema, privacy/retention inventory, UI and tests; do not change ledger history.
- The canonical profile update can store an international MoMo number and can default an absent code to `not-set`, but the inspected Admin person contract accepts local `07...` numbers and only a 4–9 digit code or null. Admin person reads return the stored values, and the page validates its rows together; source tracing therefore indicates one such record can make the containing Users or Members page fail closed. This is not a runtime reproduction. Align the producer, storage and both clients, and exercise both number forms and optional codes across the actual contracts.
- The inspected Admin records endpoint exposes a member's ledger total across groups and the dashboard's overall ledger total. Its group rows and detail do not expose a per-group balance, and the inspected Users/Members views do not establish an individual provider-wallet balance. Complete and qualify the requested balances and refresh/permission behavior; a bounded source review does not exclude another endpoint outside this path.
- The canonical Admin core pages use five-second polling and the MoMo incoming-capture panel separately polls every 15 seconds. The inspected standalone SMS receipts page uses manual refresh, and the sync entity set omits the `sms_receipt` type used by member-capture audits. Its source therefore does not establish automatic refresh for new captures; qualify a permission-scoped refresh or metadata invalidation without exposing message content. No live latency was measured.
- Ordinary member-device SMS capture records unverified raw evidence with `financial_effects: 0`; without a receiving-source binding the current processing job is `source_unresolved`, not a claimable pending job. The member capture hash represents owner/consent scope, while a receiving-account hash represents the wallet identifier; the existing source-resolution equality guard and historical-mode restrictions therefore do not normally bind this ordinary member capture to a receiving wallet. The automatic contribution journey requires a trusted source-binding and matching contract, not merely enabling capture or starting the processor. No real message or payment outcome was observed.
- Member collection and balance RPCs have inconsistent scope: the collection list is limited to 100 and excludes suspended groups, while balances include active memberships without that same collection filter. The client rejects balances outside its collection list; more than 100 memberships, suspended groups or concurrent reads can therefore lead to a fail-closed member refresh. Establish one consistent, complete authority and pagination/snapshot contract and test it; source inspection is not a runtime reproduction.
- The receiver drops a member SMS before durable queueing when its 3GPP completeness cannot be established or the protected queue cannot accept it. The production manifest removes inbox-read access. Qualify real provider multipart formats and design recovery/backpressure without exposing OTP/PIN or deleting retained evidence; no actual lost message was observed. A separate unused receipt-classifier helper has tests and must not be cited as proof of the production receiver path.
- The current iOS source has no `collect/momo_ussd` native handler; its contribution flow falls back to manual instructions. Define and test the intended iOS payment journey for the existing app update rather than assuming Android's direct handoff is present. The private share-code join can reactivate an inactive membership, so establish the intended removal/re-entry policy and test it separately from public membership.
- Native member capture can stay enabled after a same-owner session replacement, while server capture consent is scoped to a specific session ID. Re-establish or reconcile consent for the new session without discarding queued evidence, distinguish token refresh from a new session and qualify retry behavior; the suspected mismatch is source-derived, not an observed live failure.
- The local SMS gateway's timestamp validator uses `Date.parse` after checking syntax; review indicates some impossible calendar days can be normalized rather than rejected. A synthetic regression fixture was prepared but not run: one Deno probe stopped on scratch symlink accounting and a separately reviewed successor hit its heap cap before reaching tests. The original utility is unchanged. The fixture is preserved at `/Volumes/PRO-G40/Application Data/Codex/Application-Support/Collect-Reconciliation-Evidence-20261101/sms-timestamp-unrun-20261104-oeqbsjql/timestamp.test.ts`; confirm actual runtime behavior and preserve valid timestamp semantics before fixing it.
- The protected contribution journal admits at most 64 retained requests per owner/project/auth-subject partition and currently exposes no deletion or eviction operation, including for completed records. Source therefore indicates repeated use can eventually refuse new contributions. Design and qualify evidence-preserving archival/compaction with exact committed/unknown outcome rules; do not simply delete retained records or increase the bound. An interrupted native `.new` journal file can also cause later entry scans to refuse the journal; preserve it and design a separate qualified reconciliation path. Neither failure was runtime-reproduced, and no recovery action was executed.
- A profile-editor candidate now scopes its controllers, save/discard callbacks and local notifications to the observed account and session, addressing a source-traced risk of showing a prior account's dirty MoMo draft after replacement. Its widget tests are authored but unrun; no actual disclosure or failed save was observed. The sign-out-start interval before the auth event, a dirty field overwriting another field's newer same-session update, and the root confirmation sheet remaining visible across a switch are still open. Qualify the full widget flow and durable server profile-save contract before release. Similar draft scoping must be reviewed for private-group creation.
- The held gateway's first-pairing source sets its inbox checkpoint to zero; the subsequent catch-up path can locally queue pre-enrollment messages, marking them unresolved rather than excluding them. The upload hold remains in place. Review a separately qualified enrollment boundary for future pairings without changing or deleting already retained queues; no inbox or flagged recovery action was run.
- The local SMS gateway implements a deduplicated ledger-snapshot/receipt-job endpoint, but a bounded active-source search found no non-test caller that connects a committed contribution to it. An external caller may exist. Establish a durable post-commit outbox/caller and qualify same-event conflicts, retries and unknown delivery before claiming automatic balance SMS.
- The signed SMS hook opens its fence database connection without the normal Edge runtime's deployment-target validation. Generated self-host configuration uses the expected `db` host and CA, so no insecure live deployment was observed. Align the hook's database identity and CA checks without adding Supabase service keys to its scope, and test the real wrapper and adapter against invalid and valid targets. The prior isolated TLS-driver exercise does not itself qualify those production entry points.
- Self-host operator commands no longer create an empty diagnostic file for a successful subprocess. Failures and nonempty stderr are still retained privately. Completed-command stderr is not bounded by the timeout path's truncation, and a bounded search found no retention caller. Establish a bounded, evidence-preserving diagnostics policy and storage-failure tests before routine monitoring; no actual growth has been measured and existing evidence must be retained.
- The inspected restore path streams into its consumer and waits for the consumer and decryptor without a deadline; the separate backup pipeline has a deadline. A stalled process could leave restore unbounded, although no hang was reproduced. Design a qualified timeout, child cleanup and unknown-outcome policy while preserving the archive, destination and diagnostics; do not retry the flagged recovery exercise.
