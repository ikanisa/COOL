# Collect MVP source audit — working checkpoint

This is an incomplete source audit and task map, not a production approval or a replacement for the original 36-task status. It records the owner's current scope: a fresh self-hosted Supabase deployment; existing Android and iOS app updates; SMS OTP and optional Collect-managed OpenFace enrollment and remote matching; automatically eligible private-group creation, public-group joining and contribution posting; Admin management of public groups and exceptions; local SMS services; and automatic wallet and group reconciliation. Existing historical data is not needed for the first launch.

## Audit coverage

The integration worktree inventory counted 114,377 Git-visible paths, of which 110,291 were under `docs/release/` and largely consist of preserved qualification and recovery material. The active-source inventories mechanically read 723 `lib`/Android/iOS files, 245 Supabase function and migration files, 814 deploy/script files, and 1,061 test/tool/vendor/web/release files. A mechanical byte read or hash is **not** a semantic review. Reviewers fully read all 20 integration-test files, 20 additional deployment/SMS launch files and selected launch-critical backend and mobile files, but a substantive file-by-file review of the repository remains incomplete. Some exact duplicate bytes belong to platform variants, test baselines, vendored sources or historical evidence; do not delete them on hash equality alone.

The previously preserved checkpoint is commit `7fa4e5993e70904e33f993729f60a4e9c2eff052`. Its transport candidates are committed but unqualified. Earlier synthetic test results are valid only for their recorded inputs and do not prove a production deployment, real payment, device or provider delivery. Push-triggered GitHub Actions were intentionally skipped to respect the owner's instruction to avoid billing-dependent GitHub work.

## Launch tasks established so far

1. **Freeze and qualify a production candidate.** Reconcile the Admin transport source with a truthful new provenance record after actual qualification; include backend-selection, cross-realm byte chunks, pre-aborted input, cancellation, deadline and post-dispatch unknown-outcome coverage. The source also indicates immediately ready chunks could delay a timer; this is not yet reproduced. Do not rewrite historical provenance. Check the self-hosted web-server's earlier request buffering as a separate affected boundary. Resolve active dependency alerts and their source-bound toolchain guards without altering preserved historical evidence.
2. **Deploy local Supabase and SMS.** Bind an exact release and deployment profile, validate secrets/TLS and scoped Admin roles, configure SMS OTP and prove it on real phones. Private configuration may be incomplete, while production publication requires SMTP and CAPTCHA; the publication guard has a focused local regression. A local deterministic MoMo extraction option is not currently admitted by self-host configuration: the unpaused path requires the configured AI adapter and approval. Qualify a suitable local parser or an explicitly selected alternative.
3. **Integrate OpenFace.** Select and qualify the intended account-authentication capability from the owner's OpenFace platform; bind it to Collect's own account/session and consent, protect facial data and provide OTP fallback. Validate Android and iOS enrollment, matching, attack controls, recovery and supported device behavior. Existing local OpenFace source is not evidence that Collect has a production integration.
4. **Complete profiles and private groups.** Add and validate the member MoMo account name if required; the current member profile RPC omits it. Ordinary private-group creation currently stores a NULL payment destination. Implement and qualify the authorized beneficiary/payment-route flow and retain automatic eligible creation and invitation membership, without introducing routine Admin approval.
5. **Implement and verify public-group joining.** The collection detail UI permits a public nonmember to choose `Contribute & Join`, but the traced `create_contribution_intent` path calls `groupFor`, which requires active membership. The registered join operation takes a UUID invitation code, while group detail passes the public collection slug. No separate public-join operation was found in the inspected active dispatch inventory. The precise intended join timing and race-safe implementation need an actual client/server integration test; invitation-code joins must remain protected.
6. **Make qualifying MoMo contributions automatic.** Existing raw receipt ingestion is evidence with zero immediate financial effect; the traced current reconciliation path requires a distinct reviewer. Implement the owner's automatic eligibility, matching and exactly-once ledger transitions, reserving human intervention for exceptions. Do not claim provider-side settlement or refunds from ledger changes alone. Test ambiguous matches, duplicate and conflicting envelopes, retries, account/session changes and reversals.
7. **Reconcile provider wallet and group balances.** The parser can extract `wallet_balance_after_minor`, but canonical incoming-fact handling excludes failed/outgoing/reversal cases and its duplicate core-fact comparison omits wallet balance. Define conflict and ordering rules and test missing, stale, delayed or contradictory observations, fees, opening balances and unrelated wallet activity before asserting synchronization.
8. **Qualify SMS capture and confirmation.** The owner-directed Android gateway upload hold remains active; the inspected server gateway ingest route has no equivalent application-level hold, so older clients with valid credentials need separate containment and qualification. A server refusal cannot retract an HTTP body already transmitted. Member capture remains enabled by owner choice. Preserve queued evidence and uncertain acknowledgements. Implement and test the owner's automatic post-commit SMS confirmation path; the existing assisted operator flow and held dispatch do not prove it.
9. **Close member SMS session and retry risks.** Scope consent, capture and upload to the initiating session/operation and reconcile native queue acknowledgement against session transitions; native auth and queue currently use separate locks. The direct receipt wrapper generates an envelope ID if none is supplied, so a lost response followed by a fresh-ID retry can produce a second raw capture; no current in-repository caller or actual duplicate is established. Keep stable identities and a durable unknown-outcome path.
10. **Qualify Android and iOS updates.** The owner reports both apps were previously submitted and approved; treat releases as updates and verify current store identities and signing. Existing iOS release workflow references legacy endpoint values, and existing route/material-state integration fixtures contain expectations inconsistent with current group creation. Select the correct local-backend deployment profile and verify both platforms on real devices. Current integration tests frequently use fixture repositories and do not alone prove live OTP, OpenFace, MoMo or SMS.
11. **Operate and recover.** Use a fresh production database, monitor local services and gateway queues, and qualify encrypted backups and a safe restore for the actual deployment before accepting real contributions. The previously flagged recovery and roster actions remain out of scope for retry. Existing gateway retention/personal-data erasure and external-copy boundaries need qualification.

## Subsequent review and implementation checkpoint

- The self-hosted scheduler's temporary credential file is now created exclusively with mode 0600 and removed on readiness, serialization and operator exceptions. Six synthetic custody tests and nine existing operator tests passed. This does not prove cleanup after process death, failed unlink or a container retaining a mount.
- A public-join and signed-in discovery candidate has been authored. It adds a separate public-group RPC, preserves private invitation handling, refuses to reactivate removed memberships and joins before contribution preparation. Its fake-database Node tests passed 5 cases and the existing synthetic contribution-command Node suite passed 66. Ten changed Dart files passed a non-writing formatter/parse check; that is not type analysis or behavioral testing. The newly authored Flutter and PostgreSQL tests remain unrun: their existing space preflights are not met. Those fake tests do not establish Postgres locking, actual client behavior or device acceptance. Public discovery is currently limited to the latest 100 groups; the new RPC is not implemented in the retained legacy Cloudflare profile. Current user-facing source and test changes remain to be independently qualified before production.
- The member SMS session/acknowledgement race has a prepared synthetic characterization fixture but no executed reproduction; its launcher and resource profile are incomplete and prior space guards remain unmet. A proper fix must also account for existing synchronous auth-adoption contracts and distinguish the separately held gateway queue.
- Both Android and iOS release workflow sources omit the SMS-auth compile flag while the application defaults that flag to false. Bind and verify the correct local-backend profile and flags before producing either store update; source inspection does not establish the settings of a previously approved app.
- A fresh database still requires the exact migration inventory and a reviewed, source/profile/image-bound SQL10 realtime binding. Excluding historical import does not remove this installation qualification.
- Source inspection indicates the signed GoTrue SMS hook can accept an OTP into the generic gateway queue while gateway dispatch is paused or no device is ready. An accepted queue item is not a delivered OTP. This potential availability mismatch needs a synthetic hook-and-gateway test and an explicit admission/delivery contract; no actual missed delivery has been demonstrated.
- The local SMS gateway's maintenance handler covers expiry, OTP scrubbing, callbacks and alerts; a bounded active-source search found no non-test caller for its protected maintenance endpoint. An external operator may exist. Identify and qualify the actual scheduler and monitor its execution before launch.
- The native and Dart changes that add public discovery include tests of session replacement, cache downgrade and failure handling, but these tests have not been executed. The PostgreSQL integration file includes a member-roster step: do not execute a broad parent test without isolating the user's flagged roster/recovery work.
