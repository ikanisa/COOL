## Implemented controls

1. `roster_revision_limit`, `roster_request_conflict`, consumed imports, superseded revisions, expiry, unavailable groups and incompatible provenance calls stop write retries and explain the required next step. A definitively invalid review must be explicitly discarded before a corrected request receives a new UUID. The immutable source stays attached.
2. Unknown or malformed commit responses preserve the exact pending UUID and serialized request. The dialog disables submission and offers **Check saved import status**. A read never issues a write. Only a strictly validated uncommitted state permits retrying the identical saved request.
3. The status decoder requires the expected import, immutable source receipt, source hash/kind/model/expiry, valid latest revision and coherent commit state. A matching saved commit must pass the full existing request/revision/hash/mode/group/count validator before the dialog returns success. Another request's committed receipt is terminal and never returned as this draft's success.
4. Actual actor/session/feature denial clears source bytes, text, rows, receipt references and pending payloads from the private dialog. The gateway uses the current token only after verifying the original actor and Auth session, then holds that token for the request and fences its response. A mocked real signed-in A→B→A event sequence cannot revive a stale read.
5. Existing original-byte/XLSX preflight, parent-linked reviews, initial AI confidence, all-row paging, explicit affirmation, null/wrong-ACK rejection and session fences remain covered. No SQL142 or Edge contract changed.
