## Decisions that cannot be inferred from source

1. **Finality policy — finance/security:** Which independently obtained MTN/Airtel provider records or governed statements prove funds received? Who authenticates the source, handles delayed/reversed payments, and authorizes any SMS-only exception? The staged SQL explicitly does not create a provider integration (`deploy/hardening/reconciliation_approval_v2.sql:1-3`).
2. **Deployed boundary — backend/release:** Which exact SQL and Edge functions are installed? Is the historical SMS self-finalizer still executable by any service-role path? The new additive await-only migration passed an isolated full-schema replay and synthetic historical upgrade but is unapplied to an authorized hosted target (`supabase/migrations/20260928160000_sms_observation_never_settles.sql:1-36`). Have receipt v2 and reconciliation v2 been rehearsed, approved and deployed together? Source references: `supabase/migrations/20260903084000_hybrid_direct_ussd_financial_core.sql:1479-1556`; `deploy/hardening/receipt_security_v2.sql:1-2,50-60`.
3. **Separation of duties — finance/operations:** Which named people may propose, approve, finalize, reverse and break glass? What evidence format, maximum age, amount limit, exception queue and dispute escalation are accepted? Staged checks exist at `deploy/hardening/reconciliation_approval_v2.sql:37-105`; staffing and evidence authenticity are not encoded there.
4. **OTP and SMS economics — auth/operations:** Set actual global/hourly/daily OTP limits, provider spend cap, SMS receipt throughput and recovery response when the queue or parser is stuck. The OTP policy table defaults disabled in `deploy/hardening/signed_otp_limits_v2.sql:5-10`; local receiver quota is `supabase/migrations/20260815084000_atomic_sms_ingestion.sql:77-85`.
5. **Privacy and retention — owner/privacy/counsel:** Approve purposes and periods for raw body, phone/hash, device cache, financial journal, audit, logs and backup; handle legal holds and deletion requests. Raw-row deletion currently requires a governed migration (`supabase/migrations/20260903084000_hybrid_direct_ussd_financial_core.sql:373-386`). This packet makes no legal conclusion.
6. **Release stop conditions — release/operations:** Define pilot cohort, daily reconciliation tolerance, unresolved queue age, duplicate/reversal thresholds, incident owner and rollback/disable mechanism. Link every decision to the same signed artifact and deployed candidate.
