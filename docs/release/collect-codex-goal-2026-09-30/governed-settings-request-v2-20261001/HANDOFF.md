# Governed settings v2 backend contract

This additive slice delegates the existing current v1 mutation without replacing its OID, grants or body. Its public scope is `runtime_controls`. The 25 Admin families in families.json are the exact existing registry excluding user-owned notification_preferences. It does not implement propagation of SMS template, language, disclosure, recipient, sender or effective-retention policy into the canonical sending workflow.

All DTOs are closed: keys below are exact. UUIDs are canonical lowercase; digests are lowercase SHA-256 hex. Timestamps use UTC with exactly six fractional digits (`YYYY-MM-DDTHH:mm:ss.ffffffZ`). Samples expire 60 seconds after checked_at. A mutation deadline must be after server receipt and no more than 120 seconds ahead; every later wait/mutation is followed by current authority and deadline validation. All database changes roll back on postflight failure.

1. admin_list_runtime_controls_v2(p_family text,p_limit integer=25,p_after_identity jsonb=null). This is the bounded catalog within an approved family. Keys: contract_version,scope,family,checked_at,sample_valid_until,limit,descriptor,rows,next_cursor. descriptor keys: identity_fields,writable_fields,immutable_fields,nullable_fields,field_types,create_allowed,can_manage. rows keys: identity,revision,exists,redacted,content_sha256,value. It selects native JSONB identity keys from existing heads with identity>cursor before limit+1; cursor is the last returned identity or null. Field types describe only identity and writable fields; SQL relations and internal audit fields are excluded. Value uses existing v1 redaction and is projected to identity/writable fields. Family reads and current manage capability are independent. Bounds are 1..25.

2. admin_get_runtime_control_v2(p_family text,p_identity jsonb). Keys: contract_version,scope,ok,family,identity,revision,exists,value,redacted,content_sha256,checked_at,sample_valid_until,can_manage. This delegates the existing typed/redacted v1 getter and rechecks current read authority after it.

3. admin_update_runtime_control_v2(p_request_id uuid,p_family text,p_identity jsonb,p_patch_json text,p_expected_revision bigint,p_reason text,p_expires_at timestamptz). Keys: contract_version,scope,request_id,request_fingerprint,family,identity,previous_revision,revision,changed,updated_at,content_sha256,recorded_at,expires_at. The exact UTF-8 patch JSON is bounded to 65,536 bytes before parsing, then checked/delegated as a JSON object by v1. Reasons use the existing normalizer (trim its exact Unicode whitespace set), are 8..500 characters and retain only SHA-256/length privately. The request records exact input, actor and executing session in a private immutable table. Reusing a UUID with changed input, actor or mutation session is refused. An exact current-session duplicate may return its immutable original receipt within the original deadline. A successful no-op records a request receipt without an invented change event.

Request fingerprint is SHA256(UTF8(lines joined by one LF, no final LF)). Lines, in order: `collect-runtime-control-request-v2`; request UUID; family; one `field=value` line per identity_fields entry in the registry's order; expected revision as canonical decimal; deadline UTC6; SHA256(exact UTF-8 p_patch_json); SHA256(UTF-8 normalized reason). Identity fields are already restricted by v1 to ASCII text `[A-Za-z0-9_.:-]+`, canonical UUID strings or singleton true; their values cannot contain LF or equals. This hash is deliberately separate from runtime_control_hash, which omits some business fields.

4. admin_get_runtime_control_request_v2(p_request_id uuid,p_family text,p_identity jsonb,p_request_fingerprint text,p_expires_at timestamptz). Keys: contract_version,scope,request_id,request_fingerprint,family,identity,expires_at,checked_at,sample_valid_until,status,receipt. status is recorded,not_recorded,in_progress only; receipt is the exact v2 mutation DTO or null. It tries the permanent UUID advisory lock without waiting, rechecks current family-read authority and returns only the original actor's matching request. A different current session of that same actor may investigate; foreign actor is denied. `not_recorded` before the original deadline does not settle an uncertain response. No lookup creates authority, changes a revision or submits the mutation again.

5. admin_list_runtime_control_history_v2(p_family text,p_identity jsonb,p_limit integer=20,p_before_at timestamptz=null,p_before_event_id uuid=null). Keys: contract_version,scope,family,identity,checked_at,sample_valid_until,limit,history_complete,changes_only,rows,next_cursor. history_complete=false and changes_only=true: seeded/earlier history is incomplete, and no-ops are evidenced by original request lookup. rows keys: event_id,request_id,operation,previous_revision,revision,recorded_at,actor_id,authority,changed_fields,old_sha256,new_sha256,reason_sha256,reason_characters,redacted. Old events retain request_id=null. No session, reason text, content or sensitive values are disclosed. Cursor is null or exactly recorded_at,event_id; both cursor parameters are required together. The timestamp/UUID descending predicate is pushed into the indexed source before limit+1. Bounds are 1..25. Independent current audit.read is required even when settings read/manage is available.

API access to all private tables/helpers is denied to PUBLIC, anon, authenticated and service_role; only these five public RPCs are granted to authenticated. Existing publication, immutable wiring, sensitive-value, Rwanda, session and authority restrictions remain authoritative. Local SQL SET ROLE claims do not prove hosted Auth or signed-JWT behavior.

Authority observations require Read Committed and exact current role/permission evidence. The private lookup helper first try-acquires the shared Auth revocation gate and takes NOWAIT SHARE table fences on operator mode, approvals, roles, membership, grants and permission registry. Incompatible concurrent writes return runtime_control_authority_unavailable (42501), never capability=false. These fences protect insertion/absence predicates in email-transition and role authority. Matched approval expires_at is rechecked with clock_timestamp after the final row wait. The observation mirrors the current email/transition authority body while preserving every original function/OID/grant.

A mutation also takes a private UUID+actor advisory marker before the permanent UUID lock. While its first original row is uncommitted, only the matching actor marker can justify in_progress; foreign actors are denied. A visible original always requires exact actor/family/identity/fingerprint/deadline matching. The marker is serialization evidence and grants no mutation authority.

Client uncertainty bookmark: original request_id, family, identity, request_fingerprint and expires_at only. Do not retain a replayable patch or reason. Lookup may continue after original expiry under a fresh same-actor session. Mutation under a different original session remains refused. A fresh not_recorded with checked_at>=original expires_at establishes absent original; in_progress or earlier not_recorded stays uncertain.

Publication, typed patch, immutable wiring, sensitive owner-only, Rwanda, resource/quota and existing financial policy restrictions are delegated unchanged to current v1. No-op updated_at is the exact existing head time returned by v1, formatted UTC6; its receipt records a new original observation without a fabricated change event.
