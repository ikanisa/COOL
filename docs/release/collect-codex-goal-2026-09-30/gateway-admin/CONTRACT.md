# Gateway Admin read contract v1

This additive contract exposes global platform identity and immutable device/owner observations. Dispatch remains pending and unavailable. Stored device observations are not independently attested carrier, SIM ownership, network or delivery proof. Fixtures in contracts/ are synthetic shape examples; real isolated SQL outputs will be retained separately after UAT.

RPCs: `admin_list_gateway_devices_v1(p_limit integer default 20, p_before_enrolled_at timestamptz default null, p_before_device_id uuid default null)` and `admin_get_gateway_owner_request_v1(p_request_id uuid)`. Both require a live bound authenticated session, current approved `platform_owner`, and both `notifications.read` and `system_health.read`. Shared authority locks support the current email policy and revoke boundary; service-role and anonymous execution are denied. Management retains `notifications.manage` plus `system_health.read` through existing enroll/activate/revoke RPCs; reads alone grant no mutations.

The JSON schema is contracts/collect-admin-gateway-v1.schema.json. Every object has exactly its declared fields. UUIDs are ordinary valid UUIDs (no v4-only constraint), SHA values are lowercase 64-hex, counts are integers 0..1,000,000,000, timestamps are real UTC instants with zero to six fractional digits. Counts beyond that range fail closed with 55000 gateway_read_count_unavailable.

Each list echoes the requested limit 1..50. Cursor fields must both be null or both be supplied; infinity is refused. Rows are sorted by enrolled_at descending and then device_id descending, strictly before the cursor. total counts the entire visible identity set, irrespective of the page. next_cursor is present only when another candidate exists, equals the last returned row, and implies exactly limit rows. With no incoming cursor and next_cursor null, total equals rows.length. Later windows may be empty while total remains nonzero. Each response uses one committed statement snapshot; checked_at comes from its statement clock, and sample_valid_until equals checked_at+60 seconds.

Identity fields device_id, installation_id, key_sha256 and signing_certificate_sha256 are immutable public pairing identifiers. SPKI bytes, owner actor/session identifiers, raw inputs, SIM revision hash, destinations, bodies, claim tokens and sender/provider credentials are excluded. Pending has no activation/revocation time. Active has activation at or after enrollment and no revocation. Revoked has revocation at or after enrollment and any prior activation. Identity state does not attest handset readiness. Each row always has dispatch_authority=pending and dispatch_available=false.

health null means no stored heartbeat. A present health is the latest observation ordered by ingested_at and observation UUID. ingested_at is no later than checked_at. Signed client reported_at was accepted only in [ingested_at-120s,ingested_at+30s]. observation_valid_until equals min(reported_at,ingested_at)+120s, and freshness is fresh exactly when checked_at<observation_valid_until; otherwise stale. Read expiry never renews this stored observation. Permission, network, telephony, SIM selection and local pause are independent reported dimensions, including false and unknown. carrier_proof is always false. Callback counts are immutable raw OS callback observations; total=sent+delivery. No result-code interpretation or delivery conclusion is supplied.

last_owner_action is the latest retained action by recorded_at/request UUID. The receipt is the original persisted object with replay=false, and its device_id matches the row. Action maps enroll/pending, activate/active, revoke/revoked. receipt.recorded_at is no later than checked_at. This is state_at_action, not a fresh device state assertion.

Owner request reads bind the exact request UUID and original actor. A recorded request has action, the original receipt, and immutable identity. Receipt request_id equals the queried request; all device IDs agree. These identifiers allow regeneration of the five-field handset enrollment document after acknowledgement or reconciliation. Unknown includes absent and other-actor requests; action, receipt and identity are all null. Unknown is uncertainty, never approval to replay a mutation. Authority refusal raises 42501 and is distinct from unknown. Identity is retained across Auth/session deletion, but current read authority remains mandatory.

Caller-created transaction snapshots other than Read Committed raise 40001 gateway_read_snapshot_retry. Persisted receipt projections whitelist exactly their five fields, so future source additions cannot leak through reads.

Invalid list arguments raise 22023 gateway_read_query_invalid; null owner request raises 22023 gateway_owner_request_invalid. Existing public lifecycle receipts remain {device_id,request_id,state_at_action,recorded_at,replay}; this migration does not change writes or exact action reply shapes. The navigation row sms_gateway uses /admin/sms-gateway and router, with required_permission notifications.read; server RPCs additionally require system_health.read. ON CONFLICT DO NOTHING plus a locked absence check preserves changed or disabled navigation.

No dispatch grant, scheduler, financial, outbox, attempt, approval or device mutation occurs through these reads. Enrollment/activation/revocation mutations retain their existing bounded request identity, fingerprint checks and uncertainty policy. Deployment and live Auth/handset/provider evidence remain pending.
