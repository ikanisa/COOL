# Exception lifecycle — local implementation and remaining verification

The additive `20261001120000_operational_exception_lifecycle.sql` adds revision-checked assignment and deadlines, resolution only when the underlying source is cleared, immutable request receipts, original-request lookup and deduplicated escalation into a recipient-scoped Admin inbox. Inbox delivery and recipient opening are separate durable facts. The worker performs no external notification send and never marks the source resolved simply because an alert was opened.

Attempt6 passed 41/41 focused actual SQL cases on unchanged selected sources. The task-owned networkless database/container was removed. Coverage includes real assignment/replay/conflict and stale-revision refusal, current email-owner authority, bounded deadlines and request expiry, source clearing/reopening, recipient revocation/backoff, once-only delivery, overdue escalation, separate read acknowledgement, private grants/RLS and unchanged financial evidence. This is a selected migration rehearsal using a retained schema bootstrap, not a full clean/populated candidate or hosted Auth/runtime test.

The Admin implementation has strict models and SDK response validation, session/permission/freshness fences, a durable same-tab original-intent checkpoint before mutation, read-only original-request recovery after uncertain responses, and a recipient-scoped escalation inbox. It currently supports self-assignment with a one-hour deadline; approved-operator selection, custom deadlines, pagination, scheduler integration and joined workflow/escalation audit navigation remain in the updated backlog.

These results remain scoped historical evidence and are not asserted as current-source or whole-Admin acceptance.
