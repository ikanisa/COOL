# Android lookup-exception fairness: staged composed acceptance

Recoverable timeout/network failures on read-only original-request lookups consume the bounded read budget and allow later evidence work its turn. The original request UUID, exact bytes and unknown status remain retained. Network-phase IOException, deadline timeout and HTTP408/429/5xx have an explicit recoverable lookup classification. Signing/key failures occur outside that phase. TLS/trust/security causes, credentials/rejection responses, malformed or wrongly bound results, storage failures and receipt-publication failures remain closed. Mutation failures retain the existing uncertain-original behavior without retries.

Both v1/v2 reconcile and v3 archive_lookup use the read-only classification. Only transport calls are caught; result validation and authenticated receipt commits are outside the recoverable catch. Before each later callback or archive maintenance mutation, the actual caller checks current enrollment against the original attempt device and reads current journal/stop provenance. Paused/stopped gateways can preserve raw observation evidence; this supplies no SMS send or stop-clear authority.
