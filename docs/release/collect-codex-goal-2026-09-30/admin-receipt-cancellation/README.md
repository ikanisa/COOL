# Admin unstarted-receipt cancellation — scoped source evidence

The current implementation adds the governed cancellation card to the existing payment/receipt investigation. It reads the sealed v1 inspection, submits one explicitly reviewed closed reason, and reconciles the original request through the actor-bound lookup. Only positively Rwanda-scoped, pristine queued work qualifies. Cancellation records queued → suppressed and retains the primary receipt; it does not reverse a payment, send a replacement or attest carrier delivery.

The client requires `platform_owner`, `payments.read`, `notifications.read` and `system_health.read` before requesting protected evidence. Mutation additionally requires `notifications.manage` and a fresh current-identity read. The backend remains authoritative for verified email approval, actual current session, locked permissions, source evidence and revision. The immutable receipt is bound to the original request, outbox, reviewed revision and reason before it is accepted. No automatic transport retry, action replay, replacement UUID, correction or resend is offered.

Inspection and original-request lookup are independent reads with an exact 60-second snapshot TTL. Expired source state and revision are hidden. The UI exposes the backend's exact allowed/blocked reason, Kigali checked/expiry times, independent missing/unsupported/denied/busy/loading/error states, and a canonical original receipt link when recovery belongs to another receipt. A joined-investigation failure leaves a direct receipt inspection independently available.

Before the mutation RPC, the same-tab checkpoint is written and read back exactly. Its bounded payload contains the original request/outbox UUIDs, revision, closed reason and an owner digest bound to the fixed Collect project and cancellation purpose. It contains no Auth token, session, contact, body, balance or free text. Storage failure blocks submission. A fresh same-owner session restores only the reference; lookup is manual. Another actor cannot expose it. A submitted uncertainty, missing/mismatched/stale result, busy response and every `not_recorded` result retain that original reference and prohibit a new action. The backend has no signed fixed acceptance window, so a fresh not-recorded lookup even seven days later cannot establish that a delayed original will never execute. Only matching immutable recorded evidence can clear the checkpoint. A storage-clear failure retains the reference and shows already-confirmed evidence separately.
