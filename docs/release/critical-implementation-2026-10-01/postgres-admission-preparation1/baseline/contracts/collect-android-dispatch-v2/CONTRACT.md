# Android automatic dispatch v2 — local implementation contract

This contract implements the owner's delegated recorded-savings policy and the current operations policy. It does not activate a device, configure Live mode, enable the SMS flag, schedule a worker, attest delivery or change financial balances. Defaults remain Paused. The handset holds its enrolled device signing key only; service credentials remain server-side.

POST `/functions/v1/collect-android-gateway`, exact signed UTF-8 <=8192 bytes. DER P-256 ECDSA SHA256 signature and enrolled SPKI fingerprint headers remain unchanged. Version1 heartbeat, legacy callbacks/refusal/reconciliation remain supported with their published shapes. Version2 exact envelope: `contract_version:2,action,device_id,request_id,issued_at,payload`. UTC timestamps have <=6 fractional digits, issued_at within120s. No caller-supplied body, contact, balance, country, collection, principal, run, policy or segment-count is accepted for a grant.

RPCs (Edge-only service role, no direct table/helper grants) are `gateway_dispatch_grant_v2`, `gateway_arm_dispatch_v2`, `gateway_callback_v2`, `gateway_reconcile_v2`, `gateway_attempt_status_v2`. All use `(p_device_id uuid,p_request_id uuid,p_request_sha256 text,p_payload jsonb)`. Edge derives SHA256 from the exact verified body. SQL validates service authority and Read Committed again.

Actions and exact payloads:

- `dispatch_grant`: `{}`. Server derives the current Live/Live-limited run for this allowed active device, a pristine queued content2 Rwanda receipt, fixed immutable body/contact, conservative GSM basic-subset segments and cap reservation. One lifetime automatic attempt per primary receipt. The receipt remains queued, protected from assisted claim/cancellation.
- `arm_dispatch`: `{attempt_id,fence_version,body_sha256,destination_sha256,reservation_sha256,callbacks}`. callbacks is1..10 exact objects `{segment_index,sent_callback_id,delivery_callback_id}` in contiguous zero-based order, all distinct within the plan and distinct from attempt/request IDs. Callback UUIDs are lifetime unique across all stored arms. reservation_sha256 binds the saved handset reservation; it is signed device evidence, not independently attested fsync.
- `callback`: exact legacy raw callback payload `{callback_id,attempt_id,fence_version,segment_index,segment_count,body_sha256,destination_sha256,callback_kind,result_code,tp_status,occurred_at}`. callback/request UUIDs differ. kind sent|delivery, result -1..200, tp_status null|0..255. Exact original arm IDs/hash/fence/plan required; no handset delivery conclusion accepted. Prior-arm evidence remains recordable after stop, expiry and revocation.
- `reconcile`: `{target_request_id}`. Original device-scoped recording only, never a recovered permit/body. No mutation replay.
- `attempt_status`: `{attempt_id,fence_version}`. Original device's journal facts only; no dispatch or terminal compaction authority.

Response wrapper exact `{contract_version:2,action,device_id,request_id,result}`. Refusal exact `{ok:false,code,device_id,request_id,replay}`; codes OPERATIONS_PAUSED|NO_CURRENT_RUN|DEVICE_NOT_READY|NO_ELIGIBLE_RECEIPT|QUOTA_EXHAUSTED|ORIGINAL_REQUEST_RECORDED. Current-source/expiry/binding/authority/lock violations raise safe refusal; unrecognised transport/database outcome stays unknown.

Grant success exact `{ok:true,code:DISPATCH_GRANTED,device_id,request_id,attempt_id,receipt_id,run_id,fence_version,policy_revision,issued_at,expires_at,segment_count,body,destination_e164,body_sha256,destination_sha256,sim_revision_sha256,replay:false}`. Only the initial committed response releases content; replay and durable request storage are redacted. Deadline is <=30s and bounded by current run, original signed health validity and next UTC midnight. No cap refund or second attempt on lost/expired response. Body/contact digests are checked by SQL, Edge and native; native SmsManager division must match exact body/count before fsync.

Arm success exact `{ok:true,code:DISPATCH_ARMED,device_id,request_id,attempt_id,fence_version,reservation_sha256,armed_at,expires_at,replay:false,carrier_proof:false}`. Current policy/run/fence, source/contact/consent/flag, active device and latest same-SIM signed fresh health are rechecked under locks. Arm plus outbox send_started commits atomically. Handset invokes once only after original bound ACK following fsync; timeout/replayed/expired/mismatched ACK causes no invocation and retained uncertainty. Lookup is never an invocation authorization.

Callback success exact `{callback_id,recorded_at,replay,carrier_proof:false,state,sent_observations,delivery_observations,conflicting_observations}`. State send_started|observed_sent|uncertain; counts0..segment_count<=10. All planned consistent SENT `RESULT_OK=-1` produces observed_sent, only a framework callback observation. Missing callbacks remain send_started/unknown; failed or contradictory sent observations produce irreversible uncertainty. Delivery observations are raw callback evidence, not independently verified delivery. New request UUIDs preserve changed signed callback observations; changed reuse of an existing request is refused.

Status exact `{attempt_id,fence_version,state,segment_count,armed_at,sent_observations,delivery_observations,conflicting_observations,terminal_archive_ack:false,carrier_proof:false}`; state additionally granted, armed_at null for granted. Explicit false preserves terminal/late-callback compaction as an outstanding stage. Partial, unknown and callback evidence stays active, capacity exhaustion closes dispatch.

Reconcile exact `{target_request_id,outcome:unknown|recorded,recorded_action:null|dispatch_grant|arm_dispatch|callback,recorded_result:null|object}`. Recorded grant/arm result is ALWAYS the exact ORIGINAL_REQUEST_RECORDED refusal with replay:true, without content or permit. Callback lookup returns its immutable original result rather than relabelling it current.

Current verified email-owner read `admin_get_gateway_receipt_attempt_v2(p_receipt_id uuid)` is separately redacted: `{contract_version:2,receipt_id,checked_at,sample_valid_until,automatic_attempt:null|object}`. TTL exactly60s, current authority and positive Rwanda scope. Attempt object equals status plus device_id/run_id/policy_revision/issued_at/expires_at. Existing Admin human-confirmation/attempt history remains assisted-only; separate UI integration is pending. No body, contact, callback plan, SPKI, reservation hash or private request digest is returned.

Lock order is operations policy → run/principal → actual receipt → automatic attempt → device. Conflicting payment/contact/membership/route/parser/flag rows use SHARE NOWAIT after the receipt lock; contention aborts before authority. Existing financial and assisted functions are preserved, with an additive automatic reservation exclusion and receipt/arm/outcome proof guards. Lifetime primary/snapshot identity and immutable payload are unchanged. Local SQL service-role fixture is the trusted Edge boundary, not real signature/GoTrue acceptance; signature tests are separate.
