# Safe unstarted receipt cancellation v1

This is a manual owner action to stop one definitely unstarted receipt as evidenced by the governed backend records. It grants no correction, retry, resend, policy approval, dispatch or financial action. It does not attest what an unregistered handset or carrier did outside the recorded workflow. Existing seven-state transport semantics and lifetime unique(payment_id,template_key), with fixed template key/version, remain intact.

## Authority and scope

All three RPCs require the current authenticated session of a verified, approved email platform_owner with payments.read, notifications.read and system_health.read. Cancellation additionally requires notifications.manage. Read Committed is mandatory. Locked Auth session, account, email approval, role/grant and permission proof precede request/outbox locks. Phone-only transition approval never qualifies. Cancellation rechecks natural expiry after lock waits. No service-role/anon execution or private-schema/table/function API grants are given.

Only positively scoped Rwanda MoMo payment sources can return an available inspection or be cancelled. Linked sources additionally require the actual current typed Rwanda raw/parsed join. A receipt must match the posted RWF payment and immutable canonical two-line receipt journal/snapshot, balances, canonical reference, rendered body/hash and destination/hash, without a reversal journal. These checks do not change provider/financial evidence or assert external settlement proof.

## Revision and pristine predicate

A private revision head advances on every new outbox INSERT/UPDATE under that actual outbox row lock. New inserts start at 1; preexisting unheaded rows read as implicit 1, and their first UPDATE creates 2. No existing outbox row is changed or historical head backfilled during installation. Revisions are bounded 1..1,000,000,000; cancellation requires an expected revision below the cap and advances exactly once. A cap refuses instead of wrapping. Other mutable source evidence is rechecked before action; revision does not falsely claim to version every financial or policy table.

Inspection takes SHARE and cancellation UPDATE on the same actual outbox row before reading its source/head pair. Eligible receipts have state queued, fence_version 0, attempt_count 0, null claim token/worker/expiry, null suppression reason and null observed_sent_at. Any claim-request history, confirmation, attempt or gateway arm makes the row ineligible, including a previously claimed/released or privileged-reset queued row. Awaiting confirmation, send_started, uncertain, observed_sent, failed_no_send and suppressed are all ineligible. Dispatch pause and current consent do not authorize an action and are not changed: stopping a pristine receipt is independent of enabling sends.

## RPCs and exact result shape

admin_inspect_unstarted_receipt_v1(p_outbox_id uuid) returns the inspection branch of collect-safe-receipt-action-v1.schema.json. All branches use contract_version 1 and scope rw_receipt_manual_cancel. Inspection includes checked_at and sample_valid_until exactly 60 seconds apart, requested outbox_id, status available|unavailable and receipt null or the exact outbox_id/revision/state/can_cancel/reason_code projection. Unavailable includes missing and unsupported scope; no state/revision is invented. Inspection reasons are eligible, state_not_queued, prior_transport_evidence, source_evidence_invalid, already_cancelled and revision_exhausted. can_cancel is true exactly for eligible, state queued and revision below the cap.

admin_cancel_unstarted_receipt_v1(p_request_id uuid,p_outbox_id uuid,p_expected_revision bigint,p_reason_code text) accepts only operator_cancelled, recipient_review_required or content_review_required. The sole outbox state/reason change is queued→suppressed with fixed suppression_reason manual_pre_send_cancel; the existing core trigger also updates updated_at. Existing body, destination, policy/consent revisions, financial/snapshot IDs, fence, claim fields, attempt evidence, created time and primary identity stay intact. The new head, immutable action/audit record and existing derived receipt/exception events are transactional with that change. A future unsuppression is refused while this cancellation record exists.

The immutable action result binds request_id, outbox_id, expected_revision, resulting revision, action cancel_unstarted, reason_code, recorded_at, state_before queued and state_after suppressed. financial_action, send_action and provider_delivery_verified are false; primary_receipt_retained is true. It exposes no body, destination, hashes, balances, actor/session, claim or provider credentials. Same original actor/input/UUID replay under current mutation authority returns the identical original receipt without any new source write. Changed input or another actor cannot reuse that UUID. Originating actor/session UUIDs are retained privately without Auth foreign-key deletion, so a new current session of the same actor can reconcile the original evidence after session deletion.

admin_get_unstarted_receipt_action_v1(p_request_id uuid) has current read authority and a function-local 100 ms lock_timeout. It returns checked_at/sample_valid_until, original request_id, status recorded|not_recorded|in_progress and the exact actor-bound receipt or null. Another owner's recorded request is indistinguishable from not_recorded. Request-lock contention is reported only after authority is established; authority/source lock timeout raises 55P03 receipt_action_authority_busy with no request outcome. Unknown/in-progress/busy/transport failure requires manual original-UUID reconciliation and never authorizes replay, a replacement UUID, retry or sending. Read TTL refers to that read snapshot and does not renew recorded_at or other historical evidence.

All timestamps are UTC strings with exactly six fractional digits. UUIDs are canonical lowercase general UUIDs. JSON keys/enum/counter bounds are exact in the schema; semantic bindings, revision+1, TTL and reason/eligibility relation are additional invariants.

## Errors and remaining gates

42501 covers current authority/API role refusals; 40001 receipt_action_snapshot_retry refuses stale transaction isolation. 22023 receipt_action_input_invalid or receipt_action_request_conflict refuses invalid/changed intent. 55000 receipt_action_unavailable, receipt_action_source_changed, receipt_not_cancellable or revision exhaustion refuses unsupported/stale/ineligible source. Inspection/lookup 55P03 is bounded busy with no outcome. Typed PostgreSQL input failures can be rejected before entry. Timeout, disconnect or malformed response after a mutation attempt remains uncertain until original-UUID lookup; no automatic retry is part of this backend slice.

Correction, replacement content or destination, resend/retry after an attempt, cancellation of a claim or uncertain send, policy approval, unattended principal action, business event handling/ACK, scheduling, live gateway/provider authority, deployment and production acceptance remain separate open gates. This migration does not widen any existing delivery state or provide a public sender.
