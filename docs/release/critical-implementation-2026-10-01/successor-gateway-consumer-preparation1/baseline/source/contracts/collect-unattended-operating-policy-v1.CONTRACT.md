# Unattended operating-policy preparation v1

This is current-owner governance of preferences for a future unattended service. It does not complete C26. There is no executable unattended dispatcher, cap enforcer, approved financial/recipient/template/pilot authority or scheduler in this slice. Mode selection, clearing the future-policy stop preference or a fresh read does not authorize an action or promise a run. Existing assisted dispatch, signed fixed Shadow observations and any carrier work remain separate.

## Current authority

All RPCs require the actual current authenticated session of a verified, approved email platform_owner with notifications.read and system_health.read. Configuration additionally requires notifications.manage. Read Committed is mandatory. Locked Auth/account/session, roster and approval/grant/role/permission proofs precede request/policy locks. No legacy phone-only transition authority qualifies. Natural expiry is rechecked after policy/request waits. Private tables have RLS and no API grants; private helpers and public RPCs give no service-role or anonymous execution. Retained actor/session UUID evidence has no Auth deletion foreign key.

## Current view and unavailable capabilities

admin_get_unattended_operating_policy_v1() returns the current branch of collect-unattended-operating-policy-v1.schema.json. Scope is platform_global, purpose unattended_policy_preparation, and checked_at/sample_valid_until use the same clock exactly 60 seconds apart. This is read freshness; it does not renew updated_at. The singleton has a server-generated policy UUID, bounded revision 1..1,000,000,000, initialized_at/updated_at and nullable last_change_request_id. Installation defaults to configured_mode Paused and emergency_stop true without fabricating an operator action. effective_mode is Paused when emergency_stop is true, otherwise configured_mode.

All five requested modes are exposed in fixed order: Shadow, Dry-run, Live-limited, Live, Paused. Shadow, Dry-run and Paused are selectable preferences. Live-limited and Live are unselectable with OPERATING_POLICY_LIVE_AUTHORITY_PENDING. These preferences do not establish an available runner for any mode. The execution object always says unattended_dispatch_available false, grant_authority_pending true and OPERATING_POLICY_DISPATCH_AUTHORITY_PENDING.

The eight limit categories run_actions/group_actions/device_actions/global_actions and run_sms/group_sms/device_sms/global_sms remain null, enforcement false and OPERATING_POLICY_LIMIT_AUTHORITY_PENDING. No arbitrary throughput cap, currency amount, batch limit, approved recipient group or enforcement proof is invented. Future approved services must define actual values and action-bound checks. There is no limits setter.

Financial, recipient, template and pilot approvals stay null. Schedule owner/kind/cadence_seconds/next_run_at stay null, configuration_available false and OPERATING_POLICY_SCHEDULE_AUTHORITY_UNAVAILABLE. No schedule owner, native-task control, cron integration, next completion or approval is claimed or editable. The boundaries object separately reports the actual existing assisted feature flag as enabled, paused or unavailable. Policy changes never modify that flag, signed fixed Shadow observation authority or carrier work.

## Governed configuration and immutable request receipts

admin_configure_unattended_operating_policy_v1(p_request_id uuid,p_expected_revision bigint,p_mode text,p_emergency_stop boolean,p_reason_code text) accepts exact modes Shadow, Dry-run or Paused. Paused requires emergency_stop true. Allowed reasons are operator_reviewed_configuration, operator_emergency_stop (requires stop true) and operator_clear_future_stop (requires stop false). The last reason records only a future-policy preference; it cannot resume assisted sends, signed observations, a scheduler or carrier work. Live-limited/Live raise 55000 OPERATING_POLICY_LIVE_AUTHORITY_PENDING and never acquire business/send authority. Unknown/invalid intent raises 22023 operating_policy_input_invalid.

Configuration compares the expected physical singleton revision under its actual UPDATE lock, rechecks current authority after waits, and advances exactly once only when mode/stop changes. Stale expectations refuse with 55000 operating_policy_source_changed. The revision cap refuses a change with operating_policy_revision_exhausted. A new no-op request records immutable intent/audit evidence with changed false and the same revision; it does not rewrite the policy or any business source. The new head/request/audit are atomic. Requests retain original actor/session identity privately and cannot be changed or deleted.

The exact receipt binds policy_id, original request_id, expected/result revision, changed, before/after mode and stop, reason_code and recorded_at. It always denies unattended dispatch, financial/send action, approval grant, schedule change, assisted dispatch change, signed Shadow observation change and carrier-work change. It is historical action-time governance evidence rather than current effective policy. Same original actor/input/UUID replay under current mutation authority returns the identical receipt without another policy/request/audit write. Changed input or another actor cannot reuse that UUID (22023 operating_policy_request_conflict).

## Manual uncertainty reconciliation

admin_get_unattended_policy_request_v1(p_request_id uuid) requires current read authority and binds the original actor. It returns the exact 60-second timed lookup envelope, original request UUID, status recorded|not_recorded|in_progress and the historical receipt or null. Another actor's request is indistinguishable from not_recorded. Request contention is tested only after authority; mutation-held authority contention returns function-local 100ms 55P03 operating_policy_authority_busy with no request outcome. Both current view and lookup use that bounded busy refusal. A disconnect, timeout, malformed response, unknown, in-progress or busy result retains the original intent and requires manual original-UUID lookup. No automatic retry, new UUID or operation replay is authorized by absence.

Timestamps are canonical UTC strings with six fractional digits; UUIDs are general canonical lowercase UUIDs. Schema keys/types/enums/null unavailable fields are exact. Additional semantic invariants are 60-second TTL, initialized_at<=updated_at<=checked_at, valid default/last-change relationships, effective-mode derivation, receipt changed relation, revision increment/no-op relation, Paused=>stop and reason/stop agreement, and lookup request/timestamp binding.

No financial, receipt, attempt, business event acknowledgement, gateway, principal, lease, outbox, feature flag, schedule or carrier record is changed. Source truth, deployment/hosted compatibility, actual Auth runtime, reviewed business approval, action authority, cap enforcement, run/schedule ownership, throughput/device/provider validation and production acceptance remain open.
