# Joined operator entity audit v1

`admin_get_operator_entity_audit_v1(entity_kind, entity_id, limit, before_at, before_event_id)` reads one existing entity. Supported kinds are `shadow_run`, `gateway_device`, `exception`, `supervisor_identity` and `receipt`. The cursor is an optional pair; limits are 1–50. It requires a current verified email platform owner with `audit.read`, `system_health.read` and `notifications.read`; receipt/exception reads additionally require `payments.read`. Actual Auth/session, approval and role/permission authority are locked and checked again before returning. A bounded authority wait returns SQLSTATE `55P03`; denial remains `42501`, invalid arguments `22023`, and retained transaction snapshots `40001`.

The result is exactly the JSON schema. Consumers must also validate the exact echoed kind/id/limit, 60-second sample interval, newest-first unique `(recorded_at,event_id)` ordering, cursor equal to the last shown row, cursor boundary, same-kind source/action pairs and source-specific nullable fields. Receipt/payment sources require positive Rwanda scope and reject contradictory linked SMS evidence even when a receiving route matches. An unavailable or out-of-scope entity returns no events or cursor. Empty history does not prove that no action occurred. The response explicitly records incomplete history and no historical shadow audit backfill.

Sources are private retained action records: gateway owner requests; supervisor owner requests; exception acknowledgements/escalation requests; safe unstarted-receipt cancellation receipts; and newly captured manual shadow events. No arbitrary public-audit metadata, body, destination, phone, email, monetary balance, signing key, certificate, credentials or JWT is exposed. Actor identifiers and original request identifiers are retained for correlation. `revision` is the exception action's expected source revision or the cancellation's resulting receipt revision. `fence_version` exists only for a shadow event. A reason code exists only for an exception action or cancellation. These events establish the recorded action, not financial finality, escalation delivery, current health or provider delivery.

Manual shadow begin/sample/completion/explicit expiry transitions now capture both an actual public audit row and a private immutable event in the same transaction. The actual executing actor is retained; expiration performed by another owner is not attributed to the original run owner. A time-elapsed running lease has no fabricated expiry audit until a real transition occurs. Historical runs remain untouched. Existing action records can be read from their original immutable sources, including actions recorded before this migration. No scheduler, new dispatcher, business acknowledgement or authority to send is added.

The migration is prepared locally. Hosted installation, authentically signed sessions, complete historical retention, navigation and comparator acceptance remain separate.
