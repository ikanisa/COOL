Add source transformation records to `function_source_review` beside its existing candidates. For each exact schema/name/input-signature identity record the captured final `prosrc` digest; predecessor declaration/path/version/body digest; source transformation span/digest; operation type; literal needle/replacement or wrapper-template digest; and explicit limitations. Use the five classes in `classification.json`. Maintain `resolved=false`, `same_body_other_name_is_match=false`, `dynamic_SQL_evaluation_performed=false`, existing uncertainty fences and current exact-body-match counts. Unknown forms remain unknown. This corrects the reason detail without turning recognizable generated source into unsupported static lineage.

The maintained write boundary is the mapper and its existing tests, owned by one mapper worker. Add no new release checklist. Preserve the existing complete independent semantic readback behavior; any future actual output must be generated and verified from the changed mapper rather than editing captured gaps or adding a trusted manual `resolved=true` registry.

## Optional bounded reconstruction: compute expected source bytes

If root selects reconstruction as the next mapper slice, use a narrow transformation model, not arbitrary SQL execution. It must derive expected bytes from admitted original source before comparing the captured catalog digest. The current catalog contains identity arguments and `prosrc`/definition SHA-256, not function-body or pre-migration declaration bytes (`scripts/sql/collect_recovery_source_catalog.sql:89-94`). Never recover a missing expected body from the final digest, copy a final body to manufacture a match, or use the final argument names to stand in for an unproved predecessor.

1. **Identity and state.** Start from parsed exact source function bodies/argument names and explicitly supported input signatures. Replay only the allowlisted source transformations as pure metadata/string operations, in migration version plus statement order. Preserve UTF-8 bytes, newlines, trailing spaces and dollar-quoted content exactly; never strip/format/normalize a body to obtain a hash match. Builtin `timestamptz` can map to `timestamp with time zone` for signature comparison only; this does not modify body bytes or justify guessing user-defined/OUT/variadic signatures. Unknown overload, predecessor, default expression or unsupported type stops the chain.

2. **Roster schema move/rename.** Recognize only the exact finite entrypoint inventory and source block at `20260930170000_roster_fresh_auth_recovery.sql:490-548`, with the admitted migration/source-span hash. Enumerate predecessors from proved source state; do not enumerate all current final catalog functions as substitute prestate. Require the proved predecessor return type `jsonb`, ordered input argument names and unique exact signature. The two `ALTER FUNCTION` forms at 538-539 update only identity metadata and retain expected body bytes. Derive the `_guarded_149` alias from the literal suffix. Record exact original and destination signatures. Any extra statement, indirect call, catalog-dependent unknown or unavailable overload retains the original uncertainty.

3. **Roster generated wrapper.** Decode only the literal concatenations, finite name/argument-membership branches, `format` placeholders and exact body template at recovery 506-542. Implement only the reviewed `%I`/`quote_ident` behavior for safe identifier inputs in this inventory, refusing unsupported quoting/identifiers. Build ordered forwarding arguments from proved predecessor names; build guard text from the actual branch: import leaf/service helper, request/recovery/reservation lookup, Admin caller prefix and the special get-import expiry fragment. The `%s` declaration/default text is in the CREATE header and does not belong to `prosrc`; its validity is a separate signature/default question. Extract the generated `$fn$` body with its initial newline, indentation and final space unchanged, hash those expected bytes and compare the captured final body's digest. Preserve the `_create_roster_import_source_v142` two-stage predecessor chain from resource migration 181-204. The later literal private verification replacement supersedes that private body only, not the public wrapper.

4. **Header-copy aliases.** Recognize only the two explicit `pg_get_functiondef`/qualified-header replacement statements at `20261001140000_receipt_deferral_exceptions.sql:77-82`. Require proved source identity/signature/body for `collect_ops.refresh_source(text,uuid)` or `transaction_sms_id(text,uuid)`. Prove that the qualified header needle does not occur inside the expected function body. Record the destination identity; expected `prosrc` is an exact copy of those predecessor body bytes. Do not synthesize PostgreSQL's full canonical `pg_get_functiondef` output or label source equality as a rename: the block copies/recreates a function, not ALTER RENAME. If header-only scope or predecessor is unproved, keep the alias unresolved.

5. **Body-replace patches.** Recognize only literal predecessor function signatures, literal dollar-quoted/SQL/E strings, literal concatenation and `replace(body,needle,replacement)` in the exact reviewed deferral, bounded-sweep and repeat-recovery blocks. Decode SQL doubled quotes and the specifically used E-string newline escape correctly. Apply PostgreSQL literal `replace` semantics to the expected raw body, preserving all occurrences; do not silently impose an exactly-once guard on blocks whose actual guard is only `strpos>0`. For the repeat-recovery blocks enforce their actual exactly-one check. Require needle/replacement scope to be inside the body; unsupported header changes remain unresolved. Check declared predecessor `prosrc` digests where present before applying a patch. Chain execute-v2's deferral-count patch followed by its three repeat-recovery patches; queue/quota's bounded-sweep patches; capture/list's repeat-recovery patches. The predecessor digest table at repeat-recovery 5-20 supports validation but does not by itself authenticate applied history.

6. **Compare, without inferred lineage or authority.** Compute `expected_prosrc_sha256=SHA256(expected_utf8_bytes)` and compare the original captured `required_final_prosrc_sha256`. Report separately `expected_body_hash_match` and `lineage_complete`. A digest match verifies reconstructed body equality only when the predecessor and all modeled operations are established. Unknown/intervening effects retain `lineage_complete=false`, `resolved=false` and their exact uncertainty records. The two withdrawn static rename candidates must not become resolved merely because their hashes match; a complete intervening effect/prestate account is still absent. A mismatch is retained with the transformation chain, never normalized away. Keep final catalog owners/ACLs observed separately and `business_owner_assignments_verified=false` unless actual authority evidence is supplied outside this source model.

The safe starting behavior is additive typed evidence with all 36 gap statuses unchanged. Reconstruction can close a source-body equality question only for a fully admitted deterministic chain. It does not prove every anonymous SQL effect, actual installed provenance, authorized business ownership, settlement, retention or hosted parity. If closed prestate cannot be derived from original sources, use genuine retained intermediate function-definition/argument receipts from a later authorized replay; this review creates none and does not run a replay.
