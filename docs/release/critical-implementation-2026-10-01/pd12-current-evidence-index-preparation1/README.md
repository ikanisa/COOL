## Concrete additive proposal

The schema/data use38 pinned documents (including the exact original-summary copy and mechanically checked source projection),20 typed file sets,68 fixed receipt/value assertions and14 evidence records. The index hashes each relevant listed leaf/artifact; it does not execute a build, SQL, arbitrary code, provider call or inference of ownership. The schema is a reviewable contract; the proposed reader enforces the checks it uses without adding a dependency or mandatory project gate.

The read-only consumer accepts only the four observed manifest shapes: metadata maps, digest maps, metadata lists and strict SHA256 checksum lines. It rejects duplicate JSON keys, wrong candidate identity, incorrect manifest counts, unsafe/duplicate paths, missing or changed leaves, wrong typed facts/results and invalid/cyclic supersession. It retains both captured outcome and current binding status. It reports nonregular/unhashed entries and unproved physical link scope as incomplete/unverified rather than reconstructing them. Reads are bounded to128MiB/file,2GiB total,50,000 entries and60s; a bound failure reports verification-not-completed, never clearance.

Held file descriptor identity is checked before/after reading and against a final non-following direntry stat using dev/inode/size/mode/mtime/ctime. The current root/ancestor directory identities are reopened and checked before the final current-path stat, so leaf or ancestor replacement cannot retain an old FD's apparent current path. No nlink-only acceptance requirement is introduced. These are point-in-time reads, not OS immutability or source locks.

The4.24GB captured SDK physical manifest is pinned as evidence and retains the original independent physical/source/allowed8 proof; this minimal byte reader does not reinterpret its directory/link/inode semantics or perform another full SDK physical read. The active native/AAB consumer owns that source fence. Public66+3 inputs are observed exact lists, not a complete generator/transitive-set proof. Full visual, rights, legal, hosted and package areas remain explicitly unverified. No existing broad resolver is reused as a compiler graph prover: `scripts/audits/collect_evidence_resolver.py` resolves pinned evidence locations, not those source sets.
