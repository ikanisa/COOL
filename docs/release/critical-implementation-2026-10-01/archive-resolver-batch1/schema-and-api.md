# Version 1 reader input and output

Only `EvidenceResolver.from_pinned_config(absolute_path, expected_whole_sha256)` is the supported construction interface. The authorized caller supplies that expected hash out of band. Every JSON object must have exactly the documented keys; duplicate JSON keys, NaN/Infinity, invalid Unicode, unknown keys and type coercions fail. Integers exclude booleans. Digests and full repository/snapshot IDs are lowercase 64-character hexadecimal strings. Paths are canonical literal POSIX paths; relative paths must not contain empty, dot, parent, glob or backslash components. No symlink or hardlink is accepted.

Shared identity fields in the trust document, catalog and both normalized receipts are `source_repository_id` (explicit repository identity string), `source_epoch` (explicit immutable cohort identity string), `source_manifest_sha256` (the original source manifest's whole SHA-256), `repository_id` (full encrypted repository ID) and `snapshot_id` (full snapshot ID). These must all match exactly. The reader never chooses an epoch, newest snapshot, basename, partial ID or root by searching.

A root has exactly `path` (absolute), `device` and `inode` (decimal strings), and `mode` (integer POSIX mode). Source and restored roots may not overlap. The restored root must be mode 0500 or 0700 and retain the pinned real filesystem identity. All five metadata/native artifacts and the trust document must be at separate paths outside both roots, with regular-file mode 0400 or 0600. An artifact pin has exactly `path` (absolute), `sha256` and `size` (positive integer).

The trust document has exactly:

- `format: collect_evidence_resolution_trust_v1` and the five identity fields;
- `source_root`, `payload_root` and `engine`;
- `catalog`, `engine_receipt`, `engine_native_receipt`, `restore_receipt`, `restore_native_receipt` (the five artifact pins);
- `source_anchors`, a nonempty bounded list of unique `{path, sha256, size, mode}` original relative-path records. At least one anchor must have the original manifest digest. Every selected original index/manifest anchor must remain present and unchanged throughout the operation.

The `engine` object has exactly `name`, `version` and `executable_sha256`. These explicitly record the independently authenticated engine identity; the reader never installs, invokes or attests its executable.

The catalog has exactly `format: collect_evidence_relocation_v1`, the five identity fields and `entries`. Each entry has exactly `{original_path, snapshot_path, sha256, size, mode, source_mtime_ns}`. Original and snapshot relative paths are each unique across the catalog. `size` is positive; mode is exact; original mtime is a nonnegative integer nanosecond value. An original file still present must match all those original byte/mode/mtime facts. Its absence is allowed only with the entire verified input bundle. Restored bytes must always match whole SHA-256, size and mode; a digest-shaped filename is not evidence.

The normalized engine verification receipt has exactly:

- `format: collect_evidence_engine_verification_v1`, `status: verified`, `scope: complete_file_cohort`;
- the five identity fields and the exact `engine` object;
- `catalog_sha256` and `native_receipt_sha256`, bound to the externally pinned catalog and engine-native artifact;
- boolean `full_data_integrity: true` and `encrypted_repository_verified: true`.

The normalized independently verified restore receipt has exactly:

- `format: collect_evidence_restore_verification_v1`, `status: verified`, `scope: complete_file_cohort`;
- the five identity fields and the exact `engine` object;
- `catalog_sha256`, `native_receipt_sha256` (restore-native) and `engine_receipt_sha256`;
- boolean `independent_verification: true`, the exact `payload_root` and `files` (the same complete catalog entry set, without omission, extra mapping or altered facts).

Those normalized receipts are a **future verified-input contract**, not receipts generated by this patch. Current maintained database/vault capture and PostgreSQL restore tools do not verify this compiler-cache file cohort; their raw receipts are rejected. Receipt flags cannot establish encryption, independent reconstruction or authenticity by themselves. A separate authorized verifier must genuinely establish those facts and pin the exact original native reports before invoking the reader. Test-generated normalized inputs explicitly carry only synthetic fixture scope.

Python callers use `OriginalReference(original_path, sha256, source_epoch)` and one of:

- `read_bytes(reference)`: immutable verified bytes; no unchecked payload pathname;
- `verify_reference(reference)`: frozen `Resolution(original_path, sha256, size, mode, original_present)`;
- `verify_many(references)`: an all-or-nothing tuple of resolutions; bounded input consumption and no partial acceptance.

The CLI verifies one reference with `--trust-config`, `--trust-sha256`, `--original-path`, `--original-sha256`, `--epoch`. Success exits 0 with fixed status `verified_reference_bytes` and digest/size/mode/original presence. Denial exits 2 with fixed status `unresolved` and a fixed code. Neither output includes restored paths, payload bodies, credentials, raw OS errors, or release authority. Both explicitly record `archive_or_restore_operations_performed: false` and `production_release_approved: false`. Missing trusted inputs deny even when original bytes exist.

Default bounds are metadata 4 MiB per document, native receipt 16 MiB each, payload 128 MiB each, aggregate reads 512 MiB, 4,096 catalog/reference entries, 256 source anchors, paths 4,096 characters/components 255 UTF-8 bytes, and 30 seconds checked between local reads. Optional `Limits` may reduce these or increase them only within hard caps (16 MiB metadata, 64 MiB native receipts, 1 GiB files, 4 GiB total, 65,536 entries, 4,096 anchors, 300 seconds). A caller must independently enforce a real process deadline for a stalled filesystem; the reader has no engine/network/subprocess or write operation. It observes bounded file identities throughout a read; it does not claim a globally atomic snapshot or validate owner/ACL/xattr/retention/independent-copy policy.
