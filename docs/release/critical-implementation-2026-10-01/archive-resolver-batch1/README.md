# ARC-10 evidence reader implementation

The new maintained reader and 61 regression cases pass on Python 3.12.14, macOS 26.6.2 ARM64. This completes only the read-only resolver implementation slice. All 98 real first-batch references remain unresolved: each actual CLI invocation returned `trusted_inputs_required`, with zero relocated-byte acceptance. No archive, restore, engine installation, key generation, storage transfer, consumer migration, move or removal occurred. Full ARC-10 and release acceptance remain open.

`scripts/audits/collect_evidence_resolver.py` provides explicit pinned construction, original path/digest/epoch references, immutable verified byte reads and all-or-nothing metadata verification. It requires an out-of-band catalog and independently verified file-cohort engine/restore receipts, including pinned native reports and exact repository/full snapshot/root identities. No original-presence shortcut, symlink, hardlink, newest-snapshot search, placeholder file or implicit engine invocation can authorize a relocated read. `schema-and-api.md` documents exact keys, types, bounds, fixed outputs and the authority boundary.

`scripts/tests/test_collect_evidence_resolver.py` exercises genuine isolated synthetic filesystem mutations and installed Python descriptor operations. The final actual run passed 61 cases in 2.05 seconds (2.11 seconds bounded process time; 60-second real deadline). Cases falsify whole-byte/mode/size mismatches, missing/tampered catalog/native/normalized receipts, unverified encryption/full-data/independent restore scope, wrong repository/snapshot/epoch/root, incomplete restore membership, duplicate keys/paths/requests, traversal/glob/Unicode, symlinks/ancestor aliases, hardlinks, FIFO/directory payloads, source/index drift, file/ancestor swaps and in-place mutation during reads, and late changes during final metadata checks. Metadata/native/file/count/aggregate/time limits and fixed redacted CLI failures are covered. These are structural and byte-reader fixtures; no test claims an encrypted engine or independent archive restoration occurred.

Attempt 1 passed the earlier 55-case source. After adding final file-observation fences and explicit encrypted-repository input verification, attempt 2 passed the final 61-case source. Both dated logs and exact source hashes are retained; no failed test attempt is hidden and the earlier source is not promoted as the final proof. The final source hashes appear in `attempt2/result.json`, `final-source-readback.json` and the seal.

The real candidate probe re-read all 98 original regular files before and after the CLI denials, comparing whole SHA-256, size, mode and original mtime to the immutable candidate manifest. All 98 matched; 73,167,256 logical bytes remain in their original trees. The original `verification.json` tree-command index was byte-identical before/after. The denial probe deliberately provides no catalog/receipt authority and uses an explicitly unassigned epoch marker solely to exercise that earliest missing-input denial; it invents no actual source epoch or archive identity. `real-candidate-denials.json` records every original path/hash and actual exit/response, plus both complete original-source readbacks.

Existing original archive-plan/report/index/candidate bytes and maintained database/vault backup/restore sources were read only. The latter tools' actual scope cannot authorize this compiler-cache cohort; raw formats deny. The normalized file-cohort schema is for a separately assigned future independent verifier, not an invented extension to those production tools. The complete original archive-cleanup packet seal and discovery inputs are compared again in the final readback. No nine-group consumer integration or root register/CI change is part of this patch.

The integration plan in `interface-plan.md` preserves both historical tree-command links and all 98 descendant mappings. A later authorized consumer may submit exact references with verified out-of-band authority; it must keep original commands, digests, indexes, sibling logs/objects/dependencies and source comparators intact. Current original-file presence is not archive availability, and successful reader tests are not removal authority.

Owner selection and authentication of a real encrypted engine, complete metadata/sensitivity classification, retention/legal-hold disposition, key escrow/recovery, approved second failure-domain copy, full archive data check, independent archive-only restoration, all affected consumer link repairs and a real clean build/test without the archive remain required. Owner/ACL/xattr and policy preservation are outside this byte-reader proof and must be established before any operation. Actual arbitrary incoming links, restoration after any later authorized removal, external deployment/device/store acceptance and release approval also remain open. Physical filesystem stalls require an enclosing process deadline; observations are not a globally atomic snapshot.

The implementation uses descriptor-relative guarded reads supported by [Python's official OS API](https://docs.python.org/3/library/os.html). The researched engine's [official repository/snapshot identity documentation](https://restic.readthedocs.io/en/stable/100_references.html) and [full-data integrity documentation](https://restic.readthedocs.io/en/stable/045_working_with_repos.html) inform input requirements only; Restic was not selected, installed or executed here.
