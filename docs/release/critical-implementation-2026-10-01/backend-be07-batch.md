# BE-07: local admission and resource boundary implemented

The Edge handler now verifies Auth and the exact session, validates the bounded canonical request, and requires private SQL admission before OAuth and again before Google decoding. Immutable evidence binds actor, exact session, nonce, action, request hash, token hash and payload hash. Atomic quota decisions and single-use phases survive handler restart. Ambiguous outcomes retain active capacity until lease expiry, spend minute/day quota, and never allow the old token or nonce to be decoded again. Success reconciliation returns only the original still-live unused capability for the exact action; it is not a reusable verdict cache.

The retained certificate, minimum-version, licensing, package, device, timestamp and request-hash checks remain. Completion calls the existing mint body as owner and atomically records its result; direct service mint permission is removed. Attestation does not establish financial settlement. Safe aggregate decode latency/provider status are retained; raw tokens, provider bodies and request payloads are not stored in admission evidence.

`backend-be07-attempt5/result.json` binds 192 exact migration files and passes 89 real SQL checks, including positive group/SMS mint, lost acknowledgement reconciliation, used/expired capability denial, stale/revoked/replaced session denial, all six quota bounds, active/phase concurrency and both observed Auth revocation lock orderings. Its source hash readback has no drift; its uniquely labelled network-none pinned container was removed. This is a synthetic platform/prerequisite-normalized local SQL result, not a hosted observation.

Pinned Deno type-check and focused lint pass. Six helper tests plus the actual handler/Auth-client/PostgREST transport test pass with 32 steps, named environment access only and no network permission. Provider transport is a strict synthetic fetch double. Existing host-adapter suites pass all 73 tests without exclusions. Failed/stale attempts remain dated evidence and are explained in the JSON receipt.

Defaults are 10 admissions per actor/action/minute, 500 per actor/rolling24h, 2 active per actor; 100 globally/minute, 5,000 globally/rolling24h and 20 active globally; lease180s. These are engineering defaults with no claimed human approval, traffic observation or production load result. Google documents a default daily quota and recommends additional abuse controls, request binding and outage handling; the project’s actual quota and peak behavior need provider verification. Rollout must install the new Edge code first, which denies missing admission RPCs before Google, then apply migration2340 and verify effective grants. Installing SQL first would leave old Edge able to call Google before its retired mint is rejected. Actual provider/device/signed Auth, policy approval, managed platform authority, peak load, durable history/storage planning and coordinated rollout acceptance remain open. Auth client auto-refresh timers observed in the isolated fixture are a separate lifecycle review; shared production clients were not changed. Active legacy SQL consumers are being reconciled in a separate fixture receipt.
