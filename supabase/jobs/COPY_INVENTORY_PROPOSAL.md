# Operational copy inventory proposal — not adopted

Activation remains held until the owner accepts the operational copies and connects their disposition to the current retention policy. This proposal does not edit `retention-inventory.json`, widen runtime permissions, or authorize automatic personal/Auth/Storage erasure.

| Copy | Attribution and custody | Proposed policy/qualification |
| --- | --- | --- |
| `collect_ops.jobs_config` | Fixed project/endpoint, Vault name, readiness evidence digests/timestamp and probe UUID. Owner-only schema, RLS with no runtime policies. No token, email, phone or user ID. | Retained operational security/activation evidence. Pin schema/config identity in approved source inventory; do not pretend the current app/private catalog already covers it. |
| `collect_ops.jobs_dispatches` | UUID/UTC slot, native-instance epoch digest, pg_net request ID scoped to that epoch, state, Vault UUID/update time, opaque response digest, bounded cleanup count and review-evidence digest. No raw response, exception or source ID. | Retain unknowns and their original native-instance attribution. Never match a pre-restart record to a new instance's recycled numeric request ID. Bounded pruning only for terminal operational metadata under reviewed 30-day/current-month rules; preserve admission probe. It is not a financial or provider-effect receipt. |
| Vault secret/decryption surface | One service credential shared with the deployed Edge runtime; scoped by unique secret name/UUID, no member ownership. Encrypted native Vault storage, privileged decryption/rotation and provider backups have separate custody. | Private security inventory and rotation/retirement evidence. Do not expose decrypted values to inventory snapshots or clients. Existing external backups/processors dispositions still apply. |
| `net.http_request_queue` | Necessarily contains the plaintext bearer header until dispatch. Body is exactly `{ "dispatch_id": "original opaque UUID" }` and endpoint/project are fixed. Unlogged transport storage is lost on crash. | Explicit protected operational-secret copy. Effective schema/table grants must deny application/client/importer roles. Native worker removal is not proof of request rollback or secret retirement. |
| `net._http_response` | Protected raw job reply including opaque echoed dispatch UUID, default six-hour native TTL. Maintenance-only reply has counts; a changed/unpaused runtime may return receipt identifiers before the schedule detects and stops it. | Treat any such identifiers as potentially personal derived copies. Require bounded server-only attribution/selectors or an explicit blocked/unresolved disposition in approved privacy inventory. Store only opaque hashes/counts in the durable journal. Do not automatically erase raw records to claim subject deletion. |
| `cron.job` / `cron.job_run_details` | Fixed function-call command and scheduling status/timestamps. No inline token or payload. SQL function catches enqueue details and retains only fixed reason codes. | Review native log/error behavior and access. Prune only this job's completed history, never other jobs or unknown source effects. |
| Database/Edge/provider logs, backups and private operator evidence | Potential additional metadata, system copies and historical secret custody, with native provider retention. | Keep external derivative/backup/processor classes blocked until separately inventoried and reviewed. A clean journal or expired pg_net reply does not establish full erasure. |

A future approved inventory extension must bind the exact schema/helper definitions and current copy hashes into inspection, policy and commit admission, retain legal holds and durable deletion evidence, and fail closed on unknown operational copies. The caller must not obtain a raw token or all-user/global scan. No generic cleanup of these schemas is supplied as a privacy-erasure adapter.
