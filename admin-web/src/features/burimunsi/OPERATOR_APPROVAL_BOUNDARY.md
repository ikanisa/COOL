# BuriMunsi operator approval

The BuriMunsi access route in React Admin lets the protected Collect owner review an operator and explicitly approve a change. The owner needs current team and receiver permissions and a fresh email verification. The read-only review host displays the directory. The preparation-only view lets an owner preview an approval.

The page requests `approvalContract=2` from the selected group's operator directory. It offers confirmation only when the backend advertises that contract and the selected account has a current Collect identity. A predecessor that rejects the query can still serve a read-only directory. Before dispatch, React fetches the group's guarded directory again and compares the account, shared role, approval version, phone, requested capabilities and active state with the review. The backend calls the versioned approval routine with the expected principal. The database checks that principal and the current approval version under lock. [Guarded approval migration](../../../../supabase/migrations/20261116215300_burimunsi_operator_identity_guard.sql)

Before sending, React saves the original command in the owner session's tab and places its request ID, authority digest, command digest and expected receipt digest in shared browser storage. A per-group Web Lock serializes these operations. After a lost response, the owner can check the receipt by the same request ID from either tab of that session. A missing or inconsistent receipt keeps the request unresolved. An explicit retry requires the matching command in the originating tab, the shared binding, fresh verification and a fresh guarded directory.

If another tab has already verified the receipt and cleared shared recovery, the originating tab checks the server again. It clears its own command only after the collection, request ID, principal, approval version and recorded state match. For a same-service predecessor approval, an explicit receipt check also releases the original tab record after confirming its full retained intent and current owner authority. A missing, mismatched or superseded request stays pending. Production's earlier self-hosted tab records stay with that service when the browser switches to managed Supabase.
