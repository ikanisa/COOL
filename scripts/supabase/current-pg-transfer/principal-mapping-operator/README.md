# Principal mapping operator: synthetic qualification only

This operator wraps the separately reviewed, read-only principal-mapping
preflight. It has a hard managed-mode refusal: the exact four account IDs and
independently retained local cluster identity for the owner's confirmed pair
are not currently available as a reviewed, pinned plan. `MANAGED_REVIEWED_PLAN_SHA256`
is intentionally `null`, so a managed request is rejected before a connection
or credential use. Matching email cannot select a person, establish identity
or authorize another account mapping. This code does not merge accounts or
perform any write, migration, provider action or cutover.

The implemented interface receives a compact JSON envelope over a pipe or
socket, bounded to 32 KiB with a five-second input deadline. It refuses a TTY
or regular-file stdin, noncanonical JSON, duplicate keys, invalid plan/roles/
IDs, extra fields and passwords containing control characters. A separately
supplied SHA-256 pins the entire plan, including the selected IDs, preflight
plan digest, local source identity and total deadline. It must come from an
independently reviewed protected plan; calculating the pin from unreviewed
input proves only consistency, not the owner's decision.

A clean parent process starts a fresh worker with a minimal environment and
private pipe. The worker opens its own exclusively held clients, checks the
source PostgreSQL system identifier, postmaster start time, server version and
backend on the same source connection, and invokes the unchanged preflight.
The source identity check is a separate read-only transaction before the
preflight's own read-only transactions. A worker deadline, cancellation,
process-group stop checks and fixed error codes bound the call. The returned
observation contains only validated aggregate counts and comparison flags; it
omits account IDs, email, phone, passwords, SQL values, plan and source-set
hashes. Unknown or interrupted outcomes do not authorize writes or retries.

For a future managed run, the constructed target configuration is limited to
`db.rrlduytparvsjfmegalh.supabase.co:5432`, database and session user
`postgres`, with the reviewed Supabase root CA and normal hostname validation.
The caller cannot supply a different trust store, verifier or SSL option.
This path is currently disabled and no live credential or endpoint was used in
these tests. The synthetic transport uses an owned Unix-socket PostgreSQL
fixture and does not test a real TLS handshake or provider connection.

## Remaining qualification

Before any managed observation, an independent review must establish the exact
owner-selected local/cloud Auth and application IDs, the source-set and owner
decision references, and a fresh source system identifier and postmaster start
from trusted evidence. Existing retained counts and an email match are not
those bindings. The operator's loopback and database checks do not by themselves
prove a Docker container's identity, network routing or independent provenance;
the intended named source/container/image and connection-to-container binding
need separate review. A copied cluster may preserve a system identifier. The
plan, source code pin and this managed refusal then require an independently
reviewed successor; editing the input cannot enable managed mode.

The preflight's source and target snapshots are separate, point-in-time reads.
Its locks can briefly block identity writes or DDL, and do not prove complete
schema coverage, other account mappings, business-reference reconciliation,
provider/device state or quiescence. TLS peer checks require a trusted Node
runtime and clean launch; they do not attest a compromised host. The clean
launcher must start with `env -i` and trusted executable/files because checks
cannot undo code or libraries loaded before startup. Pipe input and output must
be privately supervised. JavaScript strings, process inspection, swap and crash
dumps remain secret-custody limitations.

The sole entrypoint expects the independently reviewed plan digest as its only
argument and the private compact envelope on stdin. Do not put the envelope or
passwords in command arguments, shell history, logs or environment. The exact
plan shape and synthetic values are exercised in `operator.test.mjs`; no real
plan is generated by this directory. A nonzero exit, incomplete response,
unknown worker stop or deadline means no observation is confirmed.
