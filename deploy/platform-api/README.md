# Collect Cloudflare platform API

This is the fresh canonical Workers/D1/private-R2 backend. It shares one domain across member bearer sessions and Admin HttpOnly cookie sessions.

- Worker: `collect-platform-api`, custom domain `api.collect.ikanisa.com`.
- D1: `collect-platform`, ID `a6a0d284-c445-4fe3-8e64-af5fd42491ae`.
- Private R2: `collect-platform-private`.
- Admin frontend: sibling `../platform-admin/`, bound as a service and preserving the original Admin origin.

Development and SQL tests use the committed lockfile (`npm ci`, then `npm test`). SQL tests run actual isolated workerd/D1/R2; controlled outbound replies do not prove real delivery. The eleven published migrations are immutable.

Remote deploy and migration commands require the reviewed Node 24.19.0 / Wrangler 4.151.0 **darwin-arm64** runtime profile. Other hosts, versions, lockfiles, incomplete runtimes and caller-created integrity manifests are refused before Wrangler is loaded or launched. Reuse the already reviewed offline runtime; these commands do not install or resolve packages. The complete 1,653-entry runtime manifest is independently pinned to `ac8cd687ba9a7e6376f1884687fd9e4ab9594244a32de989ff5a0274476357f1`; a different host or vendor build needs separate review.

Set `COLLECT_APPROVED_DEPENDENCY_ROOT` to the existing physical directory containing that runtime's `node_modules`, and `COLLECT_APPROVED_RUNTIME_MANIFEST` to its existing owned 0600 manifest. Every deploy/check-deploy requires both explicit physical `--bundle` and `--config`; it never defaults to unbundled `src/index.js`. The admitted esbuild parser rejects module imports in the supplied bundle, and the admission reports its actual bytes/hash alongside the config digest. Nonempty `ESBUILD_BINARY_PATH` overrides in either the real process or supplied command environment are refused before vendor loading; the admitted child receives no parser override. `npm run deploy -- --check --bundle /absolute/sealed/bundle/index.js --config /absolute/frozen/config` and `npm run migrate:remote -- --check` use npm's explicit running Node path, rather than selecting another Node or Wrangler from PATH. The operational npm process must itself be started with the reviewed Node. Migration may override its fixed default with physical `--config`. Deploy also accepts `--dry-run --outdir /absolute/empty-private-directory` together for local artifact output; this toolchain check does not authorize publication, remote migration or a different deployment target. Preserve the admission output with the release evidence. Reconcile the actual provider outcome before retrying an interrupted or failed command.

Group/profile support notes use the existing `collections.read`/`users.read` authority, including staff. `GET` and `POST /api/admin/operations/{groups|users}/:id/notes` return paginated notes or an exact retained `operator_notes` receipt. The bearer `admin_record_operator_note` RPC requires `p_request_id`. Text is encrypted with a note/entity-bound context; receipts and audit contain identifiers/digests, never the note text. Cookie authority and permission are checked inside the committing D1 batch and again before a decrypted page is returned. This adds the append-only application workflow; no retention/erasure policy approval is inferred.

Cookie Admin `GET /api/admin/sync` supplies bounded, monotonically paged domain invalidation IDs, never financial rows, note text or audit payloads. Read capabilities and the original cookie account/session are checked in the same D1 batch. Request-history invalidations are limited to the current principal. Clients reconcile on connection/recovery and refetch current authorized records; this endpoint is not a provider event feed. Team/account authority continues to be reread through the session endpoint.

The one-time offline owner bootstrap helper is not an HTTP route and has no default password. Pending MFA recovery only cancels the same principal's unverified factor after a fresh real sign-in, preserving its originating session audit. Verified factors remain protected.

Receipt capture retains encrypted evidence and an exact idempotent acknowledgement. It does not authenticate provider settlement or post money. The financial model is `canonical_evidence_ledger` (contract2); two independent real-MFA operators can reconcile retained evidence, with signed compensating reversals. Unsupported legacy provider/journal/gateway actions respond501. Never represent an unavailable capability as enabled.

Full D1/R2/Auth/configuration/key/revocation restoration and accepted RPO/RTO, provider/device checks, signing and production release approval remain separate requirements.

Enabling that optional secret or rotating actual keys requires corresponding authenticated recovery capture; these code changes do not rotate any deployed key or approve data retention.

## Member email and Google sign-in

The member login supports email verification codes and a Google OAuth broker. Cloudflare Email Service sending uses `AUTH_EMAIL` with `AUTH_EMAIL_DELIVERY=cloudflare` and a verified `AUTH_EMAIL_FROM`. Google requires the server-only OAuth client configuration and additive migration0016. Follow [the implementation and activation notes](../../docs/implementation/collect-email-google-auth-2026-10-19.md). Existing sealed release/recovery qualifications must be extended to the new source/schema before activation; local tests are not hosted/provider acceptance.
